# Published catalog activation

## Result and scope

Generate the live catalog with `pnpm catalog:activate`, then review and deliver a separate PR. No npm publication, merge, Host change, installation or runtime restart is part of this change.

The generated file is byte-for-byte equal to `catalog/candidate.json`: **17 plugin entries, 77 immutable version rows**. All 22 previously active version rows across the old three plugins are retained unchanged. The 32 frozen archives in [source PR #54](https://github.com/zts212653/clowder-ai-plugins/pull/54) include Contract, SDK and prepared installation closures; they are not 32 discoverable catalog plugins. Collective and meeting intake remain outside the official catalog.

## Observed causes

1. **The local command was not self-contained.** On base `82c5c130ef3a9cf27914407b48699cf1b57311a1`, with the prescribed Node 24.18.0/npm 11.16.0 toolchain, `pnpm catalog:activate` exited before its write phase. `catalog:check` packed Xiangqi without its generated `dist/mcp-entrypoint.mjs` and GitHub Operations without a complete build. GitHub's resulting SRI was `sha512-8v1y8QyHUYcdYVRfXCHrMW7o6mC8fw0MTdIcSJn7fTRW/9ZmL0HRt+VLULmhCrtYvXhzQ3oIYIVpmjsTS1okvA==`, rather than the reviewed/published `sha512-4pjuEdeHvjmSjyzzgOFLRKk2pK+Z38xxBbLZqiYuhFhZEWy8PKy+dJCKzQylVNv9GnUZV8Z4Ml9nJzSUP4wzbA==`. The command used `&&`, so neither registry activation nor the atomic live-file replacement ran. Adding both missing builds makes the existing activation flow succeed without changing candidate hashes or package inputs. Full CI had built these packages earlier, hiding this standalone-command defect.
2. **The release state transition was described but not enforced.** #54 explicitly retained the old three-entry live catalog and deferred activation until after publication and separate authorization. Its [publication follow-up](https://github.com/zts212653/clowder-ai-plugins/pull/54#issuecomment-6286373155) recorded partial publication. Current npm metadata independently shows all 17 selected plugin versions published by `landy_su`, with version, SRI and SHA1 matching the candidate. But the live blob is `ee0dfb9b87aed03647eef7466353fbc0eace4e09` before #54, at its merge `29595a7794486ed0e6354a35a706875998e23d8f`, and at the present base. This proves the catalog never advanced in those revisions; it does not prove which person did or did not attempt the command. Publication completion had no executable activation-completion signal or explicit continuing owner in the existing three-step instructions.
3. **Existing green checks could not expose the gap.** `catalog:live-check` checked only the entries already live; candidate checks validated packing without requiring activation. The publish job deliberately did not write live discovery, and manual npm publication bypassed that job entirely. Thus valid published candidates plus a stale, still-downloadable live catalog could pass all existing checks.

## Changes and verification

- Build Xiangqi and GitHub Operations before the standalone candidate check packs them.
- Add `pnpm catalog:activation-check`, comparing each candidate's selected immutable version row with live and verifying actual published archive bytes. Candidate-only history is not an activation obligation. Ordinary source PR CI still permits unpublished candidates.
- Run that read-only completion check after successful publication. A failure at this final step means activation is incomplete; inspect the failed step before interpreting it as an npm upload failure or retrying publication. The immutable failed run remains historical evidence after an activation PR lands; a fresh successful audit is the completion evidence.
- Run the same check daily and on manual dispatch to cover manual npm recovery. It never publishes or writes repository contents. Publishing operators retain responsibility through the reviewed catalog PR, or hand over a named owner with its PR/blocker. They should trigger the audit immediately after manual publication.
- RED: the real activation command failed for the two missing builds; regression checks detected missing builds and accepted stale/missing/rewritten live versions before implementation. GREEN: the repaired real activation command exited 0, regenerated the entire live file and verified published packages/archives; 28 targeted activation/gate tests passed, including partial publication, missing/corrupt bytes, concurrency protection, missing rows and retained history. Script-test reachability: 23/23; `git diff --check` passed.

Author dogfood is the actual activation command, catalog byte equality, preserved historical rows, and the read-only completion check against npm. The user-facing Host discovery journey belongs to the separately assigned Host work; this PR's unmerged file has not replaced the public main catalog. The repository's full `pnpm gate:ci`, independent local review and upstream PR/CI are subsequent delivery steps, not claimed complete by this note.

Risk: discovery changes from three to 17 selected plugin identities; no package code, permission or version changes. Workflow modifications affect release reporting and require the normal other-party CODEOWNER approval. No architecture ownership changes.
