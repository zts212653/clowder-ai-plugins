# Dot 云端对话插件

[English guide](README.en.md)

Dot 把已配对的 ChatGPT 云端对话接入 Clowder AI。安装实例可作为独立目标接收召唤；云端先读取原消息，再把文字回复和原始 PNG 发回同一对话。它也能向已加入对话的家猫提问，并接收这些提问的回复。

维护者：Clowder AI 插件团队。当前版本为本地候选，需要支持可寻址插件声明的配套 Host；未发布到官方目录。组件与打包验证不能代替真实 ChatGPT 账号的连接验收。

## 安装与连接

在插件管理器选择本地插件目录或作者提供的完整归档。归档携带实际运行依赖，不需要另装 SDK。完整归档携带当前构建平台的图像处理库和 sharp 的 WASM 后端；其他平台无需联网补装原生库，平台 CI 负责加载验证。临时入口仅提供 macOS Apple Silicon 的 tunnel，其他平台使用长期公网入口。

启用后打开「Dot 连接」，完整流程在插件步骤中说明：

1. 选择长期或临时公网入口，点击「生成 Server URL」或「创建临时入口」，复制返回的 Server URL。重复点击会复用仍有效的入口和凭据。长期凭据没有自动有效期；临时入口最长 24 小时。
2. 打开 <https://chatgpt.com/plugins>，选择 `+` → `Add custom MCP server`，粘贴 URL；Authentication 选择 `No authentication`。记住添加时使用的插件名称。
3. 在该插件详情确认已显示 Dot 工具和 `dot.summoned` 事件。只有未显示或定义更新后，才点击 Refresh 重新扫描。
4. 点击「生成订阅消息」并复制结果。打开 <https://chatgpt.com> 并切换到 **Work**，在目标对话中输入 `@` 并选择刚添加的插件，再粘贴消息并发送，按 ChatGPT 提示允许订阅。消息包含本次连接参数，无需额外「准备配对」。
5. 回到「Dot 连接」等待订阅结果，插件会自动发起真实往返验证，无需手动测试。只有读取原消息并回复校验码成功才显示可用，此后可在 Clowder AI 对话中 `@dot` 发送消息。

[OpenAI MCP Events 文档](https://developers.openai.com/plugins/build/mcp-events)要求在 ChatGPT Web 的 Work 对话中发起订阅；工具和事件定义变化后才需重新扫描。Work 的操作入口见[官方入门](https://learn.chatgpt.com/docs/get-started-with-work)。

Dot 在自己的实例存储中生成并保存访问凭据，通过 Host 已有的通用 webhook 路由自行鉴权。Host 只负责安装身份、声明路由、权限和运行生命周期，不管理 Dot 凭据的有效期。长期完整 Server URL 仍带 token；普通重启与持续使用会复用它，直到主人主动轮换或撤销。临时入口仍按所选期限到期，并在重启、停用或卸载时关闭。旧签名入口仅保留迁移兼容，其期限校验不变；主人主动切换到持久凭据时，需要将新 URL 添加到 ChatGPT 并完成候选订阅与往返验证。验证前旧正式连接仍受保护。「断开连接」撤销当前凭据和配对。不要把完整 URL 或 token 贴到公共对话或诊断日志。

代理为可选项，仅支持本机 HTTP CONNECT 代理；默认直接使用经过地址校验和 DNS 固定的 HTTPS 回调。别名、图标与安装实例标识由 Host 管理。

## 使用与恢复

在对话中选择 Dot 并发送消息。投递确认表示云端收到了召唤；回复位置先显示等待，正文或附件到达后接替占位。完整文字回复通过通用 SDK 结果信号结算该次任务，接收回执本身不会提前结算。每个召唤都必须先读原消息；改用其他对话或其他配对的事件标识不会获得回复权限。新原图经普通附件流进入 Host 的消息与媒体存储，可在消息里查看。

订阅成功后，插件自动发送校验事件，等待云端读取原消息并回复随机校验码，成功后显示可用。重复订阅和重启复用同一验证任务及已有证明；失败时显示原因与「重试验证」。连接可用时提供「断开连接」；轮换访问密钥在 Server URL 区完成。等待和自动验证阶段无需手动清理候选。订阅过期或配对失配时，「重新连接」返回同一 URL 的新订阅消息，请在目标 Work 对话发送；入口或密钥失效则在上方重新生成 URL。真正新建 URL 会替换旧候选，保留正式连接到新验证成功。若创建测试对话时中断、无法确认结果，自动恢复会停住并提示人工重试，避免反复新建对话。仅订阅成功或 HTTP 成功不表示模型已经回复。

停用会撤销运行实例并中止网络请求；重新启用会从持久记录恢复配对和仅用于既有提问的线程订阅。旧客户端在插件停用时不可继续调用。配置、配对、请求记录和原图在停用及卸载时保留；卸载不会删除历史消息。

## 升级与旧数据

旧连接的有效口令、配对、订阅、请求和回复标识保持不变，仅将记录归属显式映射到新安装实例。Host 在切换前复核旧授权，并只在仍有效时把旧口令绑定为该安装唯一的外部 token；失效或撤销的旧口令不会复活。导入校验安装主人、图片摘要和字节大小，返回可重试的批次回执；原文件不删除。

历史图片使用的旧地址由配套 Host 保留兼容读取。导入和兼容路由需要与 Host 一起验收；本包不会自行读取其他项目目录或改写历史消息。

## 开发

从插件仓根目录安装依赖，先构建 Contract 和 SDK，再运行本包的 typecheck、test 和 build。运行入口是 dist/plugin-entrypoint.js。旧 Host 数据迁移不属于公开 manifest/action；Host 的 Dot 兼容适配在启用前、经 owner-operation 边界调用 `./migration` 导出的批次 importer。批次接受明确的记录和原图字节，不接受服务端文件路径。

测试覆盖配对、签名召唤、先读后回复、图片流、重试、停用中止、恢复和旧数据导入。最终账号连接、设置页面及完整往返仍须在隔离 Host 中验证。
