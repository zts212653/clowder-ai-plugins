# Superagent

[Chinese guide](README.md)

The assistant conversation shows a one-time connection status without invoking a model. Opening it does not rescan history or redispatch work. New watched events include their exact source and the plugin workflow. If a coordinator finishes without recording its judgment, the conversation reports the failure and retains the event for an explicit retry; it does not automatically spend another model turn.

While enabled, a read-only baseline covers existing work in selected conversations, followed by completion and blockage checks about once a minute. The baseline reports existing completed or blocked tasks once. Later checks and restarts stay quiet when those states do not change. Each digest lists at most three changes with source links and explicitly counts any remaining changes; ask to expand the progress for details. Ordinary ongoing states, greetings and generic prompts are not proactive updates. Existing tasks keep their owners. An authoritative acceptance record takes precedence over legacy status; a finished model turn is not completed work. Outcomes without a recorded task still require member judgment from the source conversation.

A failed judgment remains available for explicit retry while other conversations continue. Status checks do not invoke a model. Pausing stops new checks; disabling and restarting preserve the deduplication snapshot.

Routine member updates, review handoffs and system notices no longer wake the coordinator one by one; read-only task snapshots follow their states. Structured member failures still reach judgment, and feedback on existing plugin work stays on its original path. Only the current user's message can authorize a new work source; member speech cannot admit new work. Unapplied non-user starts retained from an older version are also refused with an audit record. Outcomes without task records need source review when the user asks; a finished model response is not sufficient evidence of completion.

Superagent adds a resident assistant at the top of the Clowder AI conversation list. Enable the plugin, save the work it may handle, choose an Assistant Agent, choose Execution Agents and source conversations in their separate sections, then explicitly start following work.

Choose one Assistant Agent to understand requests, follow progress and delegate work. Choose one or more Execution Agents to perform tasks. One member may fill both roles. Member choices save immediately. Open the native source picker to choose conversations using the sidebar's groups, pins and ordering. Checking a conversation does not move it. Save commits the scope; Cancel leaves it unchanged, and search-hidden selections are retained. Selecting sources alone does not start monitoring or delegation.

The chosen agents distinguish new requests, feedback on existing work, background and tentative ideas. Independent work gets its own execution conversation and canonical Task. Necessary decisions and results return to the source conversation, while the main assistant conversation keeps the follow-up history.

Pause stops new intake and delegation while existing work can still report results. Subscriptions remain while paused. Disabling stops the plugin and removes subscriptions without deleting conversations, work or history. A normal restart rebuilds the selected subscriptions and resumes pending operations. The plugin cannot keep running while the local Host is closed.

Install an exact locally built `.tgz` archive through plugin integration in Settings. Public npm distribution and official catalog admission are tracked in [#214](https://github.com/zts212653/clowder-ai-plugins/issues/214) and remain on hold until the companion Host and maintainer admission decision are ready. Installation needs network access to obtain the dependencies in the publisher lock; users do not install SDK or Contract packages manually. The Host must support the generic `thread-sidebar.top` entry and native `thread-picker` renderer; updating the plugin alone cannot add the picker to an older Host.

Upgrading the same `official.superagent` preserves the assistant name, responsibility, selected members and conversations, and durable work records. Existing preference and work formats remain unchanged; a persistent read-only follow-up snapshot is added. The plugin uses Host access to selected conversations and members, with no separate external account login. The selected members' providers may process these messages and consume quota. New work must stay within the configured responsibility; publishing, deleting data and other significant actions still require their existing authorization.

Report issues and feature requests in the [plugin repository](https://github.com/zts212653/clowder-ai-plugins/issues). This is a local-archive trial without official catalog admission, without a claim that real models reliably detect every anomaly or automatically complete recovery across members.

For development, run `npm run typecheck`, `npm test` and `npm run build`. Runtime dependencies use exact published SDK, Contract and Zod versions with `npm-shrinkwrap.json`. Use the pinned artifact toolchain and canonical packer described in the repository contribution guide. Unit tests script model decisions; real-model semantics, complete Host journeys and cross-platform acceptance are recorded separately. Candidate publication, catalog activation and actual installation are separate verification boundaries.
