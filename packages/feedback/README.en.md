# Feedback plugin

[Chinese guide](README.md)

`0.1.0-alpha.2` pairs with the panel HTTP revision in Host PR #1762. Both HTML (`GET /api/plugins/official.feedback/panel`) and business operations (`POST feedback`) use declared HTTP routes. The sidebar only discovers the page; there is no separate mounting action call or PluginUiPanel envelope. The opaque iframe keeps its owner and activation checks, replacing alpha.1's `invoke` business bridge. Reports and screenshots use shared HTTP streaming responses; disabling the plugin invalidates old panels.

The bottom sidebar entry resumes the last selected feedback. Choose New feedback for a blank form without deleting earlier records, then choose Bug or Feature (`bug:` / `feat:`), optionally add a title, and provide a description or pictures. Detailed reports are generated by an existing configured Agent Client. Direct submission also works without an agent. Automatic submission returns the actual Issue URL after remote title/body verification. Manual creation remains available with inline text copy, binary PNG copy and original image downloads.

The prominent Feedback records view shows independent drafts, analysis progress, reports awaiting delivery, manual handoff, uncertain deliveries and published Issue links. An unfinished record never blocks a new one. Analysis member, destination and project scope are collapsed under settings. Input and settings changes are saved automatically. With the paired Host `close.guard` capability, X/Escape waits for image processing and draft saving; a failed save keeps the panel and input available for retry. Reopening or refreshing restores the selected record, pictures, type, destination, analysis member and project directory. An older Host displays an upgrade notice and still requires an explicit Save draft before closing. Migration preserves originals and publication receipts; older overwritten content cannot be reconstructed. Opening the manual page means awaiting web submission, not confirmed publication.

Requires a `next` Host containing PR #1762, which ports #1732's generic sidebar capability and adopts panel HTTP. The complete release also pairs with the merged HTTP timeout fix [#1955](https://github.com/zts212653/clowder-ai/pull/1955) and close-before-save integration [#1972](https://github.com/zts212653/clowder-ai/pull/1972); the latter must merge before this plugin is published. Analysis uses ordinary configured members, threads, messaging and optional `runtimeInfo.get()`. Once activated in the official catalog, search Plugin Settings for `问题反馈`, install, test and enable it, then open the bottom sidebar entry. Installation is optional; older Hosts without these capabilities are unsupported. For source development, build with `pnpm --filter @clowder-ai/feedback build` and install the packed archive locally.

The default target is the public `zts212653/clowder-ai` repository. Configure `githubToken` or `gitlabToken` using secret fields. Never put credentials in destination JSON or CLI arguments.

Set `destinations` to a JSON array. Each profile contains `id`, `label`, positive integer `revision`, `provider` (`github`, `gitlab`, `organization-cli`), `mode` (`both`, `manual`), `project` (`namespace/repository`), `apiBaseUrl`, `issueCreateUrl`, `visibility` (`public`, `private`, `unknown`), and `attachmentOrigins`. URLs require HTTPS, no credentials, query or fragment. The manual URL must identify the configured project's new Issue page. GitLab uses an API base such as `https://gitlab.example.test/api/v4`. Increment the revision whenever configuration changes. Every configured byte, report and image digest is bound to approval; edits revoke approval. Client/account/destination facts also have a confirmation revision. Native destinations that cannot be resolved are explicitly unknown. Internal profiles never fall back to a public service.

GitLab uploads approved image bytes through its project Markdown upload API and verifies remote SHA-256 before referencing them. Public project uploads may be directly accessible even when an Issue is confidential. GitHub image submission requires an organization-approved `attachmentCommand: { executable, args }` and allowed `attachmentOrigins`. Without this adapter the UI preserves all images and offers manual creation; text-only automatic submission still works. Independent attachment command URLs currently require credential-free HTTPS readback.

The organization CLI adapter uses `command: { executable, args }`, fixed argv and no shell. A wrapper may use existing `glab`, internal CLI or gateway tools. It reads one UTF-8 JSON request from stdin and writes one JSON response to stdout, within 30 seconds and 2 MB. Only OS paths, temporary directory and native authentication HOME directory environment variables are inherited. The wrapper owns authentication.

Requests contain `protocol: "clowder-feedback/v1"`, `op`, a target (`id`, `project`, `apiBaseUrl`, `visibility`) and `payload`. Supported operations:

| Operation | Payload | Response |
| --- | --- | --- |
| preflight | empty object | principal, project, visibility, canCreate, attachments |
| upload | submissionId, attachment with base64/mime/sha256 | url, sha256, visibility |
| create | submissionId, title, body including marker | id/iid/number, url, title, body/description |
| read | id | actual remote Issue content |
| reconcile | submissionId | object containing issues array, retaining submission markers |

Issue links must be actual server-returned URLs inside the configured project. Opening a page or a successful CLI exit is not publication evidence. Attachment URLs must match allowed origins and remote bytes must match the approved digest.

Paste screenshots directly from the clipboard or use Add images to select local files. Both inputs share previews, removal and persistence; ordinary text paste is unchanged. Up to four PNG/JPEG/WebP images are accepted, with separate original and send-copy limits of 4 MB each and 8 MB total. Images are decoded to PNG locally and metadata is removed again on the server. Preview and confirmation bind the actual send copy. Original bytes are retained separately for local downloads and never uploaded automatically. Images are not sent to the model. Inspect and obscure sensitive pixels yourself. Text filtering cannot guarantee removal of business secrets.

The panel declares a 15 MiB HTTP request budget, including originals, send copies, the encoded report and analysis settings. Adding or saving images checks the full encoded request; an oversized batch preserves the earlier draft and asks the user to reduce or crop images. Saving continues during report review and manual handoff. A version conflict offers Save as new draft without overwriting another window. Failed saves remain visible in the fixed footer; the paired Host offers Close anyway with a warning that unsaved changes may be lost.

The versioned recipe is `src/recipe.ts` (`feedback-diagnosis/4`). Choose the analysis member explicitly; an optional project directory sets the diagnostic scope, rather than selecting an existing conversation. Bug analysis includes bounded recent error evidence after local redaction; Feature analysis gathers requirements and suggestions without error logs, with an explanation and expandable input preview instead of duplicate consent checkboxes. The configured Client may send that sanitized input to its cloud model. Raw log files are not uploaded as Issue attachments, though the final report may quote relevant evidence. Ordinary response history provides exact input association and durable completion, recovering missed live events and panel reopen without invoking again. New replies use readable Markdown title/body; legacy signed JSON is also accepted. Status polling updates progress in place. Results are sanitized again, previewed and edited before explicit publication; stopping the wait does not forcibly terminate the Client. Read-only guidance remains a prompt, not a sandbox.

Image bytes live in the Host-provisioned dataPath under content hashes; CAS records contain metadata only and stay within the real Host 1 MiB value limit. The durable journal fences writes before any remote mutation. Each upload receipt is checkpointed. Failures before Issue creation allow explicit edit recovery while retaining receipts; unknown creation is never resent. Known Issue links remain visible while readback is pending. Ambiguous results are reconciled without another create attempt; a missing match does not establish failure. Recovery examines up to 100 recent Issues. Disabling or uninstalling the plugin does not delete retained drafts, images or receipts.

Run `pnpm --filter @clowder-ai/feedback test`, `typecheck` and `build`. Synthetic transport tests do not replace real model, enterprise adapter or remote publication acceptance.
