# 旧候选退出与合入后修复

旧版本生成的 candidate 可能不符合更新后的 landing 文件树合同。恢复不能依赖这个错误候选先通过正常准备或合入核验。

## 使用入口

当前同步的“本笔同步内容”直接提供“退出或修复本笔同步”。先检查原候选与 PR，再根据结果操作。同页展示检查时间、内部 main、原分支与修复候选。主要操作区可直接跳到这里，无需查找技术日志。

| 检查结果 | 下一步 | 证据与限制 |
|---|---|---|
| 仅本地候选 | 确认退出 | 不运行旧候选检查，不读取外网 |
| 已发布分支，平台查无 PR，且没有建单意图 | 保留分支并退出 | 不能把创建结果不明当作查无 PR |
| 原 PR 打开 | 关闭原 PR 并回读后退出 | 仓库、地址、源分支、目标分支和候选 SHA 必须匹配 |
| 原 PR 已关闭 | 回读后完成退出 | 不再次创建或关闭其他 PR |
| 手动或 Git 创建，不能查询关闭状态 | 平台关闭后明确人工确认 | 只记录人工确认；状态变化需重新检查 |
| 原候选已合入 | 预览并创建独立修复 PR | 不回退 main，不覆盖原 candidate 或旧分支 |
| PR 创建结果未知、身份不符、候选被改写 | 暂停，核对原对象 | 保留所有记录，不猜测“尚未创建” |

main 有无关提交、平台 diff base 变化，都不等同于原 PR 合入。合入归属以原候选的 Git 祖先关系及准确 PR 状态为证据；修复必须证明原候选已进入 main。无法证明的 squash／历史改写需先核对，不能据此生成自动修复。

## 退出与明确重试

1. 在写锁中固定当前交付与原 PR 地址，先保存退出意图。暂停轮次、关闭自动合入。
2. 只查询内部 main、原候选分支和原 PR；不依赖 GitHub Token、旧项目检查或旧候选文件树校验。
3. 已打开 PR 只关闭准确匹配的对象，随后再次读取状态及 Git 关系。
4. 回执丢失时保留退出意图。刷新、重启后优先查询原对象；查到已关闭便完成退出，不重新建单。
5. 退出完成后记录 CANCELLED，接受游标不变，清空待执行队列。旧分支、Issue、SHA 映射、配置记录与执行历史保留。
6. 用户明确继续后重新读取原目标，使用新交付身份、新分支和新 PR；以稳定的外部 Issue 身份复用原 Issue。

手动确认绑定最新的检查指纹（内部 main、候选 SHA、分支与 PR 地址）。旧表单不能关闭新交付。勾选不写入浏览器持久存储，刷新后重新确认。人工确认不能替代准确的平台查询，也不能授权覆盖远端分支。

## 已合入候选的修复

原交付保留 `candidate`、`base`、`commitMappings` 和 `developmentMappings`。修复使用独立的计划、候选、分支、PR 和最终接收记录：

```text
原 PR / 错误 candidate（已合入）
  → 预览当前 main 与目标 landing 的修复差异
  → 用户确认计划
  → 新修复提交（父提交为冻结的当前 main）
  → 项目检查 → 发布新分支 → 创建／回读修复 PR
  → 平台审核合入
  → 树与历史核验 → 保存修复 SHA 对应 → 核对原 Issue → 暂停等待明确继续
```

修复候选使用 landing 文件树，声明的内部保留路径从当前 main 取值。预览先核对原候选到当前 main 之间没有新增的未声明核心改动，防止覆盖后来有效工作。预览树通过私有对象引用保留，完整迁移也能带走尚未发布的计划。

修复 PR 的创建意图在请求前落盘。创建响应丢失后只查同一来源标识；不会另建修复 PR或 Issue。Git 创建回执缺少地址时，只补登记原修复 PR 的具体链接。默认保持人工合入，原轮次的自动合入授权不继承到修复流程。

合入后必须证明实际 main 的树、冻结父提交和修复候选一致。通过后新增 landing → 修复 SHA 映射，原逐条映射不改写；原 Issue 的接收条件再按修复映射判断。元数据失败时只补写原 Issue／接收记录，不重新准备代码。

## 修复本身需要退出时

修复 PR 尚未合入时，可检查并退出这笔修复，关闭回执丢失也可重启后继续查询。旧计划、修复分支和 PR 存入修复历史；新的计划使用新的身份。原同步及 Issue 不变。修复已合入则不能退出，必须先核验实际结果。

## 验证边界

专项入口为 `pnpm --dir packages/repo-sync test:recovery`，包含真实的合成 Git 仓库、合成平台 HTTP 回执和浏览器操作。覆盖退出、显式重试、原 Issue 复用、main 独立前进、人工确认过期、关闭／创建回执丢失、修复 PR、刷新重启与修复再退出。

这些证据不替代真实内网平台的授权、审批保护和实际网络验收。不上传内部仓库、Token、日志、文件内容或生产台账到公共 PR。
