# 新建反馈与反馈记录

用户已要求：未投递的问题不阻塞新问题；清楚查看草稿、分析中、分析完成待投递与已投递记录；新建时只选择 bug/feat、填写简短描述或图片，详细报告交给 Agent。

## 体验与归属

- 复用当前侧栏面板，不新增 Host 入口。打开默认是空白新反馈；顶部始终可进入“反馈记录”。
- 新建页只展示类型、选填短标题、描述和图片，一句隐私提醒。分析成员、目标和项目目录折叠为设置；模型/投递边界在实际分析和投递前说明。
- 类型由用户选择，标题统一 `bug:` 或 `feat:`；图片可作为唯一描述材料。分析仍不把图片交给模型，没有文字时诚实说明证据缺口。
- 每条反馈拥有独立草稿、分析、投递围栏和修订号。旧单投递未知时仍可创建另一条，但不能重发旧单。
- 反馈记录显示状态与明确动作，手动打开网页只标记待网页提交，不能当作已投递。

## 实施与兼容

1. 增加 owner 范围的反馈 ID 索引；正文、图片和分析按反馈 ID 存储，图片继续复用私有 vault。不改 Host/SDK。
2. 首次读取幂等归档旧单槽草稿和分析，保留原键；只有来源一致才关联，未匹配的旧分析独立保留，不覆盖用户草稿。
3. 所有更新、分析、确认与核对显式携带反馈 ID；事件映射只写对应分析。已有发布去重和回执语义保留。
4. UI 默认新建，自动保存有效输入；新建/切换前等待保存，异步状态返回不得切换记录或覆盖另一个草稿。记录页刷新后台状态，分析页静默更新进展。

## 验收

- RED→GREEN：A 尚未投递/结果未知时创建 B；两条分别编辑、分析、投递和重新打开，互不覆盖。
- 旧数据迁移后可见且重复打开不重复迁移；不同用户互不可读；未知远端结果保持围栏。
- `bug:`/`feat:` 前缀、无标题自动概括、图片单独反馈；新建页无多段排查说明。
- 最终包实际面板验证新建、记录、返回、关闭重开、分析完成回到正确记录、自动与手动投递；平台写入使用替身，不创建公共测试单。
- 原 runtime 只热更新插件，保留原配置和全部旧数据；真实模型只补新的流程证据，不为重复刷新状态反复调用。交付附验收报告与限制。
