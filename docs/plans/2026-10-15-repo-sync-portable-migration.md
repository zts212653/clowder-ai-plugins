# 配置模板、完整迁移与认证恢复

本方案在插件仓 PR #77 的现有分支交付。用户已授权实施，不拆 PR。

## 用户旅程

设置提供“导入 / 导出配置与同步进度”。配置模板携带仓库、分支、同步模式、保留文件规则、内置检查和平台连接设置；不携带基线与历史。完整迁移包额外携带整个项目台账、每笔交付、执行记录、Issue / PR 意图与映射、提交 SHA 映射及对应 Git 对象。

完整迁移先等待当前任务和执行记录安全结束，再冻结源项目、暂停轮次并导出。源项目继续可读历史，HTTP、后台观察器、CLI 都不允许继续写。取消移交必须确认接收端尚未启用或已停止，再重新核验和明确启用源端。跨机器的唯一执行者由操作者确认；离线网络不提供分布式互斥保证。

接收人选择文件 → 查看仓库、规则、历史数量与原 PR → 导入为独立项目 → 补充本人认证 → 核验环境和仓库 → 确认唯一执行环境并启用 → 回到工作台继续原轮次。模板启用后仍需通过原向导确认起点，不会擅自初始化；完整包沿用原起点，不重建台账。

## 数据与执行边界

- 包版本必须与当前插件版本一致。128 MiB JSON 文件上限，逻辑记录 32 MiB、Git bundle 80 MiB 上限；超限明确拒绝，不截断历史。
- 配置使用字段白名单，不携带 Token 值、环境变量值、SSH 密钥、Git 配置、钩子、检查工作目录或机器绝对台账路径。自定义检查、命令适配器和自定义推送选项明确拒绝自动迁移，避免执行外来命令或削弱检查。
- 完整包包含私有仓库地址、代码和历史，属于私有交接文件；无认证信息不代表可公开发布。源码或 Issue 正文自行写入的敏感内容不属于认证存储，导出不保证其脱敏。
- 包采用版本化 JSON、逐文件 SHA-256 与整体内容摘要。摘要用于检测损坏，不代表可信签名。导入把文件视为数据，只恢复允许的逻辑文件及 `refs/sync/*` Git 对象。
- 目标路径由本机工作台生成，位于私有配置旁；不采用包里的绝对路径。拒绝链接、路径穿越、重复条目、异常引用、损坏对象、运行中任务和仓库绑定不符。
- 历史任务保留输入哈希、时间、步骤和冻结配置；仅改为本机项目 envelope 身份，并另记迁移来源。平台来源键、创建意图与 SHA 映射保持不变。

## 原子性与恢复

检查文件不登记项目、不访问远端、不创建对象。导入先写隔离暂存目录，验证逻辑记录与 Git 对象，写暂停门禁与回执，再原子移动到全新项目目录，最后登记项目索引。已有项目、配置和台账不覆盖。

同一包的项目身份从内容摘要确定；重复点击、网络丢回执和重启后重复导入返回同一项目。移动完成但索引未保存时，以原回执完成登记。暂存失败保留隔离文件，不暴露为可运行项目。不同包不得管理已有相同内部仓库与合入分支。

导入后持久保存 `IMPORTED` 门禁；导出源为 `EXPORTED`。认证和只读访问通过后，明确启用写为 `ACTIVE`，但轮次仍暂停。启用当时重新核验，不仅相信之前成功报告。后台服务和刷新、重启都不能自动解除门禁。

## 异常交互

缺失或过期的内部 / GitHub Token，在失败步骤就近提供处理按钮，展开当前项目的密码输入并聚焦。保存后保留原同步范围并提供“继续原同步”；未确认认证前不重试写操作。连接、工具、证书和迁移门禁错误提供对应设置入口，不把 Git 凭据问题误导成 API Token 问题。历史错误不得替另一笔当前交付执行恢复。

## 验证范围

使用私有临时 Git 仓库和可记录写入次数的本机平台 HTTP fixture，验证跨路径、完整映射、未知创建结果恢复、不重复建单、候选 / 合入状态、刷新重启、损坏文件、路径与权限、索引提交中断和同包重试。真实服务浏览器验证导出下载、文件预览、独立项目导入、认证直达、错误重试、启用门禁与窄屏。全量插件检查、构建和干净安装验证通过后更新 5220 正式试用服务及 PR。

本机模拟平台测试不替代用户内网 CodeHub 部署验收；文档与 PR 结果会区分证据范围。
