---
title: Preserve and reconcile final pull request provider facts
created: 2026-11-06
status: implementation
---

The accepted result is a durable, rebuildable view of a merged or closed pull request's final provider HEAD, review commit associations, merge identity and actual CI provenance. Historical native delivery and assignment records remain historical records. A provider approval cannot create native delivery.

The R2 failure-mode audit changes three state contracts. Automatic provider admission reads immutable provider lifecycle/fact events, never native case terminal state or a transient projection. All reviews/comments in a legacy terminal snapshot share that admission decision. Projection cursors also retain pending cross-subject operations in the same saved value; retries drain them outside the subject lock. Issue associations enter the PR's journal with their own source, so future links cannot be seeded into old merge events. Unchanged complete reads advance one bounded collection checkpoint instead of adding business events; its source-event reference and CI watermark survive projection rebuild and reject older changes.

| Persisted provider evidence | Automatic collection |
| --- | --- |
| No provider closure, including a natively declined case | Capture a new provider terminal transition |
| Provider closure with no terminal facts | Refuse the complete historical batch; use the authorized native action |
| Closed-unmerged history followed by a verified current provider opening | Record that new period, preserve the native terminal fence, capture its later closure |
| Enrolled terminal facts | Refresh actual changes; checkpoint unchanged read times |
| Projection temporarily missing | Use the same journal evidence, with the same outcome |

The historical action uses projection-only replay. It preserves existing link metadata and unfinished operations but does not execute them, manufacture new association/cascade events, open work or wake another owner. Normal workflow projection owns those operations. Rebuild no longer starts with the final cache's complete link set or runs a pass that cascades old merges using future links.

Native review and provider lifecycle are independent. A native decline or provider closure permanently fences automatic native assignment/CI/cloud/readiness observations for that review; later provider reopening does not change its reviewer, delivery history, lease or wake. A newly verified open HEAD after an unmerged provider closure records `pr.open_observed`, enabling the new provider period without filling the old closure. It is captured from tracking, exact state reconciliation and a current provider read for signed reopened webhooks; it never sends a GitHub reopen request or revives a done subscription. Immutable merged provider subjects cannot reopen. Available provider update/request times reject stale period observations; unchanged open HEADs update the existing bounded checkpoint rather than growing the journal.

Old terminal snapshots remain inspectable while an open-period marker supplies current display state/HEAD and unknown current CI. New terminal snapshots clear that marker. Closed→merged or later closed periods retain source-bound reviews and `ciHistory`; prior CI becomes current only for the same HEAD when its observation is at least as new as the new closure. Sparse new-period input cannot erase evidence or promote an old pass to current CI. Current complete API results still replace unknown. Provider identity is verified before an open observation can serve as admission evidence.

Architecture cell: GitHub provider → existing Community event journal → existing projection and inspection read model.
Map delta: add a provider-only terminal observation within these owners and one bounded native reconciliation action; no new store, service, scheduler or review lifecycle.
Why: existing terminal collection discards final facts, and retrying an active verdict is correctly fenced after closure.
Canonical source: `CommunityEventLog.ts` and `community-projector.ts`; provider observations do not own native verdicts.
Consumer evidence: `rg -n 'observeTracking|collectTracking|providerObservation|fetchPrState|emitCommunityEventLogOnly|graphQlPrToPollResult' packages/github-operations/src` covers single/batch tracking, webhook, reconciler, inspection and CI readers.
Claim guard: terminal provider observations preserve final facts and cannot open review work → production-entry tests of collection, projection/rebuild, reconciliation and installed-package native dispatch → RED when final HEAD/review/CI is absent or historical delivery/ownership changes.

1. Reproduce final-fact loss at the real CommunityRuntime and GitHubProvider boundaries. Use in-memory Host storage, no production state. Keep a trustworthy RED, then repair the production path.
2. Carry typed terminal facts, including source/subject/commit-bound CI and review commit IDs. Use a deterministic journal event and an optional rebuildable projection field. Fold committed events in journal order even when independent producers apply them in a different order. Save the consumed journal cursor atomically with derived state; cursor adoption retains existing cross-subject issue links. Native last-delivered, reviewer identity, terminal fence and failure evidence are unchanged.
3. Preserve the same facts from tracking, verified webhook payloads and repository reconciliation. Automatic collection admits a new terminal transition or refreshes an already enrolled fact; it cannot enroll legacy terminal subjects missing facts. Those require the bounded native action. Fetch real terminal CI for exact and batched readers, including pagination. A newer complete unknown CI result supersedes an older success; a sparse webhook with no CI does not erase the latest complete observation. Older observations cannot regress final identity or CI.
4. Expose one authenticated, repository-configured action taking only an existing PR subject. It re-reads GitHub under current caller/lifecycle fencing and appends only terminal provider facts. It cannot accept supplied facts, register tracking, wake reviewers or write a delivery verdict. Invalid/mismatched subjects, commits, CI or incomplete provider reads cannot become positive evidence.
5. Run package typecheck, affected behavior suites, independent non-author review, and a fresh tarball consumer through actual native action dispatch and readback/rebuild. Candidate validation uses disposable storage; no public package or production migration is performed by this change.

Cost: one journal fact per substantive terminal transition, with one bounded collector progress row per enrolled subject for fresh read/CI watermarks. The progress row references committed facts and is retained in private storage independently of derived projection rebuilds. Pending existing cross-subject operations occupy the source projection until acknowledged. There is no new resident process, standalone store or polling lane. Active subjects and enrolled terminal subjects request complete reviews/CI on the existing repository cadence, including after pass/fail, because checks may change. Legacy terminal subjects use existing summary reads. Normal projection updates read only the new subject journal tail; legacy cursorless projections replay once, and explicit duplicate/rebuild requests can replay again. Proven old bootstrap associations are read from their source issue journals; recovery does not backdate them into an older PR merge.

Validation commands come from this repository: `pnpm --filter @clowder-ai/github-operations typecheck`, `pnpm --filter @clowder-ai/github-operations test`, `pnpm --filter @clowder-ai/github-operations build`; source behavior tests run with `node --import tsx --test`. Candidate verification uses `scripts/pack-publish-artifact.mjs` and an isolated `npm install` of that tarball. Repository commands provide no formatter beyond TypeScript lint; `git diff --check` checks edited whitespace.

The implementation, independent review and candidate consumer are authorized here. Publishing, merging a branch that triggers publication, catalog activation, installed-runtime upgrade and production historical reconciliation require their own existing authorization to be verified after the candidate is reviewable.

Recovery contract: each committed provider-period journal event must recover both request-observed and provider-update comparison clocks without a checkpoint. An older-source or missing checkpoint cannot weaken an observed opening. Checkpoints only advance source-matched read watermarks; they are not a prerequisite for stale-event admission. After append succeeds but checkpoint persistence fails, a recreated collector must reject the old close and rebuild the same open period without lifecycle or notification effects.

Provider-period reduction is a single pure contract over accepted journal events. It owns open/closed/merged progression, period identity, monotone provider/request clocks, automatic enrollment and complete-fact period binding. Collector admission, history reads and projection consume that same result; a rejected event remains only journal evidence and cannot affect the next decision. Same-period sparse enrichment preserves known clocks, while summaries changing the period cannot expose old CI as current. Lifecycle event IDs include the new period after reopening. Normal lifecycle projection owns linked-issue cascades; facts-only historical repair remains projection-only and creates none. No new worker, store or polling lane is introduced.

Each accepted state transition retains both prior request and provider clock floors. Same-state enrichment preserves those boundaries. Equal, second-resolution provider timestamps require a request strictly after the previous state boundary; an ambiguous webhook waits for the existing complete API collection path. A missing closing timestamp never exempts an older request from admission checks. Period inference remains separate from that exemption: sparse evidence with a missing timestamp does not by itself invent a new period. A transition row also carries any checkpoint-advanced floors, so append followed by checkpoint failure cannot weaken journal-only recovery. Old projection caches reconstruct their prefix before consuming these fields.

Unchanged-content coalescing requires complete facts already bound to the target period. Identical facts following a reopening still commit that new closure once. Tracking and scheduled lifecycle rows carry the same complete API request clock as their associated facts; a webhook delivery time is never substituted for a provider request.
