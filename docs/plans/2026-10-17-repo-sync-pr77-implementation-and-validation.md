# PR #77 自动合入等待与工作台实施记录

对应批准方案：[方案](2026-10-16-repo-sync-pr77-auto-merge-and-workbench-review-plan.md)。仍使用 `feat/repo-sync-plugin` 和原 PR #77，无新增 PR。以下属于作者实施与验证记录，不替代独立代码审查或内网现场验收。

## 1. 已落地行为

| 范围 | 实施与约束 |
|---|---|
| CI 等待 | pending/running/checking 保持正常等待；后台 10／20／30 秒退避，30 分钟默认预算可配置；缺审批／手动任务显示人工等待；失败 CI／冲突才阻塞 |
| 自动合入授权 | 默认关闭，本轮主动开启；写入前核对当前候选 CI SHA、平台条件、原 PR、base/head 与候选分支；不直接推 main，不使用 squash |
| 未知写入结果 | 合入意图先落盘；请求超时、5xx，或成功 PUT 后 GET 失败，均保留原请求并只读回查；重启不重复 PUT |
| 超时与错误 | 自动等待超时后显式恢复才重置预算；只读暂态错误最多连续三次退避，401/403 直接提供处理入口；记录落盘失败等原门禁保留 |
| 第四／第五步 | 平台合入事实独立保存；第四步完成后第五步核验 Git／Issue。第五步失败不抹去已观察的合入事实，接收游标仍只在核验通过后推进 |
| 流程节点 | 共享版本化计划，预先定义五阶段与固定子步骤；逐对象进度归属已有节点，命令证据不增加业务节点；merge-intent/platform-merge 明确归属第四步 |
| 用户展开 | 默认全部收起，包括当前和异常节点；支持展开／收起全部。手动状态按项目、绑定、笔次和当前／历史视图保存，刷新及轮询不自动展开 |
| 历史和来源 | 历史在同页选择与查看；Issue／commit 数量常显，具体 Issue、开发提交和内外 SHA 按需展开，保留原配置和时间信息 |
| 设置 | 已启用项目不再出现初始化步骤条或同步长日志；一个主要保存动作处理可编辑配置、会话 Token 与分项只读检查。项目改名移入设置，冻结值可见且只读 |
| 认证恢复 | 新统一保存接入原恢复流程；Token 失效可从失败步骤跳设置，粘贴保存后继续原轮次；不丢失 PR／Issue／候选和历史 |
| 兼容与私密性 | 新建不提供 Git push-options 创建 PR 选项；旧方式兼容。Token 不进入配置、任务、日志、草稿、模板或迁移包；新观察字段纳入台账／迁移校验 |

## 2. 对方案的实施调整

- 1280–1439px 也使用约 248px 右侧操作区：实际截图及几何断言显示，底部操作条会占据首屏并遮挡五阶段。更窄屏幕采用正文操作区，移动端正常滚动。
- 五主节点和异常摘要常显，技术命令证据按需展开；不把所有命令同时摊开，也不承诺长历史和所有设置绝对无滚动。
- 浏览器回归发现，历史区域重绘会收起并导致搜索框失焦；现同时保存历史、Issue、提交及基线详情的手动展开状态。
- 原评论把 `task.persistence.status === FAILED` 当作普通业务失败原因，这部分未采纳。它保护记录保存失败；真正的普通失败停止链是轮次 FAILED。该保护保持有效。

## 4. 最终执行结果

- `pnpm --dir packages/repo-sync test`：375 / 375 通过；此后等待预算传递的小修通过对应的“成功写入后 GET 失败”回归。
- 浏览器脚本共 25 个，均取得通过结果；其中阶段回归 8 / 8。覆盖完整过程／版本旅程、认证恢复、历史、刷新、同端口服务重启、异常与撤销恢复、迁移、多项目及新等待设置。
- `pnpm --dir packages/repo-sync build` 和 `lint`：通过，Manifest／MCP 3 / 3；完整 Node 套件包含打包后 fresh-consumer 安装与启动验证。
- `git diff --check`：通过。Biome 对本轮变更无错误，保留两处既有 CSS `!important` 的提示，分别保证 hidden 语义与减少动画偏好；不通过删除这些声明改变行为。
- 1440×900 和 1366×768 的五阶段／主操作首屏几何断言通过；设置和等待界面在 1440、1366、1280、390 宽度无横向溢出。已实际检查截图并据此压缩首屏、取消遮盖输入的设置保存浮层。
- 本机正式试用：[工作台](http://127.0.0.1:5220/)。已确认 production 状态、端口归属及正式 CLI 启动命令；内嵌浏览器可打开。此入口沿用原私有配置路径，启动时该路径没有已保存的项目配置／台账，页面正确显示默认待配置项目，未注入演示或测试仓库。

最终浏览器检查期间将样式拆成两个文件，早先启动的部分用例未加载新资源而失败；已用新服务构造重新通过对应视口用例。另修正测试中无条件重复切换已保存展开状态的问题。25 项通过结论使用修正后的对应结果，未把中途失败算作通过。

正式服务以当前分支运行；停止或重启后，会话内 Token 需由用户重新提供。内网 CodeHub 的实际版本、CI 字段、审批保护和账号权限未接入验证，不能把本机协议夹具结果当作内网部署验收。PR 保持 Draft，尚未合入。
