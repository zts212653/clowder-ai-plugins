## Implemented interface and validation boundary

Architecture cell: plugin package / external protocol. Map delta: Dot business moves to
packages/chatgpt-dot; Host target/queue remains A, Host cutover/media compatibility remains C.
The package imports public SDK/Contract only, with no Host source imports or member/key registry.

- Contract beta.40 adds addressedDelivery.method and migration.method as separate closed declarations.
  The latter is a non-UI, owner-operation-only dormant settings action; it is not in active actions.
- SDK beta.22 requires addressedDelivery's handler once and revokes it with the activation.
- MCP contribution dot-mcp, path mcp, method dot.rpc. Independent admission verifies x-dot-credential;
  shared admission uses a Host-created owner-http-request write context with the exact installed instance.
  Raw Pro/Agent keys never enter the package.
  Each action retains its request context in a private async scope; existing async SDK ports check its
  signal/fence before and after calls, storage CAS included. Streams capture that fence for later reads.
  Dormant migration uses the same fenced storage port for all records and cached receipts; a revoked
  owner or disposed settings carrier cannot turn an awaited read into a subsequent authorized write.
  Stop drains every admitted action, including asks and roundtrip tests. A reused configured secret
  cannot carry an old ask across a changed pairing attempt, and repeated disconnect retains first revocation.
  Follow-up delivery carries the matched question's pairing attempt into dispatch admission, so a
  reconnect during ask lookup cannot redirect its reply into the new pairing. Startup failure, including
  settings configuration initialization, revokes and settles the runtime before releasing the running slot.
  Shared source authorization rechecks ready state and the original attempt after both awaited Host
  reads. Original-image streams recheck that attempt before each chunk, including after file reads and
  between iterator calls, so reconnect/disconnect cannot turn a completed old read into a new effect.
  Lower writers receive the captured owner-and-pairing fence: direct and proxy callback transports
  invoke it after TLS readiness before any HTTP headers/body, including pairing verification; image
  retention invokes it after temporary-file writes and the caller repeats it before metadata CAS.
- Migration batch version 1 carries ownerUserId/sourceInstanceId, optional legacy connection,
  up to 100 dispatches and up to 8 images {metadata,png_base64}. Connection is imported before dispatches,
  images after their dispatch. Older attempts are retained without reauthorizing them. Pure CAS merges
  preserve live evidence on retry, including an interrupted batch whose receipt was never written.
  Legacy authority is rechecked by C without mutating the old key registry. A later revokedAt strengthens
  the same imported connection through CAS; stale active inputs and later timestamps cannot replace
  the first revocation. Contention and a missing receipt cannot restore the credential.
  Complete PNGs are atomically linked into their final path without replacement. Conflicting concurrent
  imports fail without changing the winning original; identical writers reuse its bytes and receipt.
- All production dependencies are physically bundled by the canonical packer. This private candidate
  adds no live catalog row and no publishing workflow. The local archive targets darwin/arm64.
- New pairing order: prepare -> enable runtime -> subscribe cloud callback -> nonce-bound roundtrip.
  Imported pairing may start directly after dormant migration. Disable aborts live transport and revokes
  actions; config refresh replaces transport without changing pairing. Uninstall retains user data.
- Existing consumers keep SDK beta.21/Contract beta.37. Catalog checks validate their exact source lock
  rather than requiring every plugin to upgrade to the new pair. Fresh-consumer coverage checks both.

## Review loop brake: complete failure-pattern audit after R5

Before requesting a sixth review, all ten findings from R1–R5 were reread together. Original
accepted scope and ownership above remain unchanged. The repeated failure is treating a successful
admission/read as authority that survives later asynchronous work. Three separate lifetimes apply:
Host owner request, enabled runtime, and the package pairing attempt. A final error cannot undo a
published message, callback body, retained original or yielded byte.

R1/R2 established request-local owner fences across SDK ports and dormant migration. R1/R3/R4
established explicit pairing identity through asks/followups, source lookups and stream chunks.
R5 shows the remaining boundary: network DNS/CONNECT/TLS and temporary file writes happen below
those checks. The correction is to carry one captured pairing fence into the concrete effect writer,
not add another upstream check and assume lower layers are synchronous.

Audit coverage: connection begin/subscribe/unsubscribe/disconnect/evidence; all runtime source,
reply/image/ask/test/followup/stream effects; direct and proxy callback writers; immutable PNG retention;
active/settings startup/stop; dormant migration records/receipts. Migration has owner-only authority
and intentionally imports revoked historical attempts, so a live-pairing requirement there would be
incorrect. Owner-authorized connection changes also must remain possible without an active pairing.

Implementation after the audit: compose the captured attempt with the existing owner
fence, carry it to direct/proxy callback pre-write hooks after TLS readiness, and use it after temporary
PNG creation plus before image metadata CAS. Verification challenges carry their unpaired attempt
with the same rule. No new Host API, external permission, authority fallback or persistent authority registry.
Tests must observe zero actual callback requests and zero canonical image/metadata retention after
revocation at these suspension points; eventual error responses alone are insufficient.
The new asynchronous transport fence is itself abortable: a stalled read-only authority check cannot
outlive the proxy deadline or keep its TLS socket open. This cancellation applies only to authority
checks; admitted mutating Host calls still drain before stop completes.

R6 added a separate precondition-ordering finding: a message rejected by the Host byte budget must
not leave a reply digest or ask reservation that prevents a shorter retry. Text construction now uses
the canonical Contract messaging semantic validator before either reservation. Ask schema validation
and publication share the same sorted/deduplicated mention formatter, including JSON escape/UTF-8
overhead. Standard JSON Schema cannot express serialized UTF-8 bytes; tool content descriptions
expose the generated 65,536-byte budget, while Zod and runtime validation enforce it. Existing
50,000-character caps remain, and an exactly-at-budget payload is accepted. The sibling send paths
were checked: image captions are capped at 500 characters; roundtrip text has only a fixed-size nonce;
PNG validation, target validation and nonce checks already precede their relevant reservations.

## C integration finding: retained data after reinstall

C reproduced a lifecycle composition gap on reviewed source c9e7ec5: an identical legacy batch
returned the previous installation's receipt after uninstall/reinstall, and bypassing that receipt
then failed the retained connection's instance comparison. Package storage is retained by plugin,
whereas a newly installed instance has a new ID. Neither layer may treat these identities as equal.

Receipts now key completion by the target instance plus the unchanged canonical batch digest.
Old unscoped receipts remain retained evidence but cannot complete a new target's import. The
receipt payload and public batch schema do not change. Only the current Host-created owner-operation
fence may CAS-relocate a retained connection with matching owner, attempt, credential, legacy key
provenance and pairing code. The source connection must still match the declared legacy source ID.
The CAS copies current runtime evidence and keeps the first non-null revocation. Host installed
authority fences obsolete contexts; there is no data-path or caller-payload authority fallback.
Dispatch/image-only batches cannot relocate a connection and must follow its successful import.

Failure-mode sweep covers connection, cached receipt, dispatch-only batch replay, PNG/history,
old credential authentication, receipt failure, CAS contention, concurrent stale/revoked retries,
conflicting identities, and obsolete owner fences. The new module-level journey stops/uninstalls,
opens a new module and instance against retained storage, imports through dormant settings, starts,
and authenticates the old credential. It retains old receipts, runtime evidence and original bytes.
Revoked retained state remains revoked even if the old source still says active. C's real Host
installer/generic-webhook RED remains the external acceptance check after new reviewed bytes; these
component tests do not claim that Host integration or a real cloud-account journey has passed.
