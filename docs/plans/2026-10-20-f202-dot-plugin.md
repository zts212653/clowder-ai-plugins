# Dot plugin migration B

Accepted source: `thread_mu8dg6h7l2x4ohsk#0001792496572158-000196-0a0473ac`;
Host F202 “Follow-up direction: addressable plugins and Dot”, develop_base
`8a90e1423eb4d6d38578edbdaeaafd8f2c2cd3e3`.

Before: Dot uses a protected member identity and Host-specific connection, return and image routes.
After: an installed Dot receives admitted addressed inputs, sends signed summons to its paired cloud
conversation, and returns source-bound text/images through ordinary plugin messaging and streams.
The owner still chooses the cloud conversation, pairing, enablement and reconnection.

Ownership: provider owns its cloud conversation; package owns connection, pairing, signed webhook,
source-read/reply grants, image originals and MCP protocol; Host owns installation/grants, instance ID,
alias/icon, message admission/queue, durable messages, media materialization and lifecycle.
No member identity, global message subscription, new queue, AgentKeyRegistry or Host store import.

1. Observe failing package journey tests: pair -> verify -> addressed input -> read -> reply/image;
   hostile source/credential/reconnect cases, idempotency, disable/restart and migration retention.
2. Implement package state over existing storage CAS and files under the instance data directory.
   Secrets from existing legacy state remain private; new pair credentials are package-owned.
   Owner operations require the Host-supplied owner context. External MCP has a separate package
   credential and never trusts caller author/user/target fields as Host authority.
3. Preserve existing MCP tool/event names and signed callback protocol. Keep public URL pinning,
   bounded TLS/proxy transport, source revalidation and PNG decoding limits.
4. Consume A's exact addressed-delivery declaration; B owns no Host routing. Declare only implemented
   actions; identity is display attribution, never a cat. Replies use messaging.send with stable keys.
5. Provide a non-destructive, owner-bound legacy importer. Preserve pairing attempt/credentials,
   dispatch/reply evidence and original image bytes; install-instance remapping is explicit and audited.
6. Build/pack using canonical scripts; verify self-contained artifact in an empty consumer, record full
   hashes and exact version, and hand exact interface/artifact to C for isolated Host acceptance.
7. Risk-matched quality gate, non-author review and PR. No npm publish/live catalog activation.

A owns addressability/queue/alias/icon; C owns legacy Host data relocation, shared MCP transport,
Settings/receipt replacement and final isolated Host request/reply acceptance. Component simulations
are not evidence of a real ChatGPT account or installed Host journey. Keep these claims distinct.

## Implemented interface and validation boundary

Architecture cell: plugin package / external protocol. Map delta: Dot business moves to
packages/chatgpt-dot; Host target/queue remains A, Host cutover/media compatibility remains C.
The package imports public SDK/Contract only, with no Host source imports or member/key registry.

- Contract beta.40 adds addressedDelivery.method and migration.method as separate closed declarations.
  The latter is a non-UI, owner-operation-only dormant settings action; it is not in active actions.
- SDK beta.22 requires addressedDelivery's handler once and revokes it with the activation.
- MCP contribution dot-mcp, path mcp, method dot.rpc. Independent admission verifies x-dot-credential;
  shared admission uses a Host-created owner-http-request write context with the exact installed instance.
  Raw Pro/Agent keys never enter the package.
  Each action retains its request context in a private async scope; existing async SDK ports check its
  signal/fence before and after calls, storage CAS included. Streams capture that fence for later reads.
  Dormant migration uses the same fenced storage port for all records and cached receipts; a revoked
  owner or disposed settings carrier cannot turn an awaited read into a subsequent authorized write.
  Stop drains every admitted action, including asks and roundtrip tests. A reused configured secret
  cannot carry an old ask across a changed pairing attempt, and repeated disconnect retains first revocation.
  Follow-up delivery carries the matched question's pairing attempt into dispatch admission, so a
  reconnect during ask lookup cannot redirect its reply into the new pairing. Startup failure, including
  settings configuration initialization, revokes and settles the runtime before releasing the running slot.
  Shared source authorization rechecks ready state and the original attempt after both awaited Host
  reads. Original-image streams recheck that attempt before each chunk, including after file reads and
  between iterator calls, so reconnect/disconnect cannot turn a completed old read into a new effect.
- Migration batch version 1 carries ownerUserId/sourceInstanceId, optional legacy connection,
  up to 100 dispatches and up to 8 images {metadata,png_base64}. Connection is imported before dispatches,
  images after their dispatch. Older attempts are retained without reauthorizing them. Pure CAS merges
  preserve live evidence on retry, including an interrupted batch whose receipt was never written.
  Legacy authority is rechecked by C without mutating the old key registry. A later revokedAt strengthens
  the same imported connection through CAS; stale active inputs and later timestamps cannot replace
  the first revocation. Contention and a missing receipt cannot restore the credential.
  Complete PNGs are atomically linked into their final path without replacement. Conflicting concurrent
  imports fail without changing the winning original; identical writers reuse its bytes and receipt.
- All production dependencies are physically bundled by the canonical packer. This private candidate
  adds no live catalog row and no publishing workflow. The local archive targets darwin/arm64.
- New pairing order: prepare -> enable runtime -> subscribe cloud callback -> nonce-bound roundtrip.
  Imported pairing may start directly after dormant migration. Disable aborts live transport and revokes
  actions; config refresh replaces transport without changing pairing. Uninstall retains user data.
- Existing consumers keep SDK beta.21/Contract beta.37. Catalog checks validate their exact source lock
  rather than requiring every plugin to upgrade to the new pair. Fresh-consumer coverage checks both.

Observed RED: addressed manifest rejected before schema change; declared delivery handler rejected
before SDK activation update; pairing not implemented; interrupted import lost live evidence;
read-only shared caller incorrectly admitted. The corresponding targeted tests now pass.
Packed artifact proof uses offline npm install with an empty cache, then the actual manifest/default
entrypoint for setup/enable/stop/restart in an isolated process with no workspace dependency resolution.
This proves package closure and component lifecycle, not real Host/account acceptance. C owns the
paired-version Host migration, old-gallery materialization and real external roundtrip. No production
configuration, catalog, runtime process or user data store has been modified.

Webhook requestBodyLimitBytes defaults to 1 MiB, accepts positive safe integers up to 15 MiB,
and is declared at 15 MiB by dot-mcp. Generated constants expose both budgets from the schema.
Host C enforces per-contribution byte limits before invocation and retains credential stripping.
Migrated transport tests exercise loopback proxy/TLS, DNS pinning, fake-IP rejection and deadlines.
