# 仓库连接、Issue 认证与首次关单规则确认

继续 PR #77。用户实际使用反馈：两侧字段错列；CodeHub 被迫填写 GitLab API 项目 ID 与环境变量；提交消息关单确认没有可理解的操作。

## 用户旅程与实现边界

- 连接页使用两列独立仓库分组：外部地址 / 交付分支；内部地址 / 合入分支 / 网页地址。移动端以完整分组顺序排列，不能把两个仓库字段交错。
- Git 认证与平台 API 认证分别说明。用户随后在 [#77 的测试评论](https://github.com/zts212653/clowder-ai-plugins/pull/77#issuecomment-6165865422) 提供了实际 CodeHub 证据：GitLab v4 API 创建可用，所用 Git push-options 不创建 MR，网页与 API 不同域，Node 需企业 CA，MR 使用无 `/-/` 的旧地址。采纳协议与错误发现，不把基础创建当成完整同步验收，也不复制内部项目 ID、域名或账号。
- 新增内置 `pullRequests.mode=gitlab`，与 Issue 共用 API 项目及认证。Git 负责候选传输，平台接口查询 / 创建 / 回读 MR，沿用原创建意图、稳定交付标识与 head/base 保护；未知结果不再次创建，不自动合入。旧 Git 意图不被改选 API 静默重置。
- GitLab 兼容方式可填写 Issue 网页链接，生成项目路径与 API 地址建议，无须寻找数字项目 ID；高级选项可修正。不是任意平台接口自动发现，子路径部署及其他协议不猜测。
- Token 支持密码框直接输入，单独受会话令牌 / Origin / 项目 / 配置版本保护的接口接收；仅存在当前服务内存，不进入配置、任务、历史、URL、日志、浏览器草稿或安装制品。环境变量保留为已有配置与高级用法。服务重启需重新输入；提交 Token 不等于 API 验证。
- 移除连接步骤中的关单勾选项，在首次准备同步的同一流程内展示：外部 `Closes #123` 可能影响内部同号 Issue；给出隔离测试仓的推送与合入核对步骤。未确认时不能发布候选。确认可在已有基线后单独保存，不改模式 / 文件规则 / 接受游标，并记录配置观察。

## 验证

### 用户补充后的最终规则

- 主区域推荐填写 Issue 网页链接及 Token，实时展示同域 API 与项目路径的推断结果；API 地址与项目 ID / 路径标为可选，默认折叠在高级设置内，独立 API 域名 / 特殊部署时显式覆盖。Token 变量只在环境方式必填。
- 原 `INVALID_ISSUE_CONFIG` 合并多项检查且丢失字段信息。现在用固定字段 / 原因白名单定位当前提交的表单，展开错误区域、聚焦输入框、保留普通草稿；不返回 Token、输入值或原始异常。末尾 `/` 和 `%2F` 项目路径可规范化；旧合法配置的表示与绑定身份保留。隐藏共享设置时保留既有 API 域名。
- 接管已有仓库时 U0 保持历史已接收版本，I0 使用内部当前 HEAD；旧 I0 错误定位到字段。读取自动填当前 I0 并保留 U0，不修改内仓。专项路径保留、核心一致与历史保护仍生效。
- 按用户最新范围决定，移除三方文件合并、在线冲突编辑及执行模块。两种模式均只支持完整内部保留路径，其余核心严格一致；区别仅在 tag 单笔交付与逐 PR 过程交付。旧非空 `mergePaths` 明确拒绝并保留配置 / 台账，不能静默迁移；历史旧规则仍可作为只读证据显示。
- 对应回归含错误 RED、字段与安全序列化、仅链接配置、高级覆盖、基线重读、真实 Git 专项保留、二进制精确保留、原对象恢复、旧配置不改写及安装包不含已移除模块。

先观察字段分组、人工模式隐藏字段、密码草稿泄露、缺少凭据入口及已有基线无法保存确认的 RED。HTTP 验证 Token 只在内存使用，不能跨项目复用、旧配置拒绝、清除 / 服务停止失效，不返回 Token，API 校验只读不建单。真实浏览器覆盖模式切换、Token 输入、草稿 / 刷新 / 多项目、当前步骤确认与 1440 / 390 排版，再跑相关及全量回归。

## 作者验证与交付边界

### 首次配置推进与原生 GitHub 读取

用户反馈首次保存后仍堆积仓库、PR 和 Issue 设置，commit 填写无明确推进，执行状态落到页面底部；旧草稿还会重新打开已完成步骤。改为服务端配置 / 基线状态决定当前步骤：仓库完成后默认折叠，当前卡片进入 U0 / I0；保存成功聚焦 U0，读取结束聚焦下一项输入；核验成功突出工作台入口。执行区域置于当前基线卡片，运行、失败、取消和待补存状态一次定位，轮询不反复抢焦点。平台设置与保存位置按需展开，设置与认证反馈跟随原操作；历史和审核路径仍在同一流程。

用户确认 Windows 在“读取到目标版本的 PR 清单 → 读取 GitHub 仓库元数据”报 COMMAND_NOT_FOUND。源码定位到原 gh-api.mjs 调用 gh，而 Git 可用 / 已登录不意味着 gh 可执行。按用户授权移除来源查询的 gh 依赖，直接使用原生 fetch 调用 GitHub REST / GraphQL；Git 仍负责代码、tag 和对象，不使用 commit 消息猜测完整 Issue 关闭关系。保持完整分页和既有关闭事件来源证明，不做文件三方合并。

公开 REST 的有限匿名读取不等于完整过程同步：关联关闭事件的 GraphQL 需要读取令牌。当前项目提供独立的 GitHub 读取认证，受 loopback nonce、Origin、项目、绑定、配置版本和运行任务保护；仅内存保存，服务停止清除，文件规则调整可保留相同来源的认证，不能跨项目或来源自动复用。保留 GH_TOKEN / GITHUB_TOKEN 环境方式。界面不把“已提供”说成“已验证完整权限”；只读验证与实际 PR / Issue 查询各自诚实反馈，不扩大到写权限。

客户端只连接 api.github.com，禁止重定向与跨来源分页，限制响应大小、页数和重复游标；缺失 / 失效认证、权限、限流、TLS、网络、非法 JSON 和不完整关联明确拒绝，不能把读取失败当成无 Issue。取消会中止 HTTP。开始来源扫描前检查已提供读取认证，不再让用户先执行多步才发现缺少依赖；接受游标和原交付保留。通用命令诊断区分工具不可启动、执行目录缺失与认证失败，错误只使用固定标签，不携带私有路径、参数或原始输出。

已观察可信 RED：保存后活动输入为空而非 U0；读取结束没有回到 I0；缺少 gh 时 REST / GraphQL 均报 COMMAND_NOT_FOUND；不存在的工作目录误报缺工具；认证入口 404。新增用户旅程和诊断检查保护这些行为。公开上游的真实原生 REST 与 GraphQL 只读查询亦已验证；匿名出口请求实际遇到限流，客户端正确分类，使用当前已授权凭据的单次内存验证完成完整关联分页。此证据不代表用户内网端到端验收，令牌和响应细节不对外发布。

最终验证：Node 全量 191/191；十五组浏览器旅程通过（批次先通过前十一组，再在修正密码框断言后通过后四组）；语法 / Manifest / MCP 3/3；182 个代码与相关 CSS 的 Biome 检查零警告，行数和 diff 检查通过。全量回归曾发现新认证组件在纯渲染路径提前读取浏览器 location，已改为请求时加载作用域并重新跑完全量；多认证入口下的刷新检查同时确认所有密码框为空。无 gh 的 Windows PATH 场景覆盖真实 Git tag、原生 REST / GraphQL、令牌缺失 ×、项目内存认证、未推进基线与恢复后的两笔 PR / 共享 Issue 关闭来源。补充实测独立 loopback 服务的认证 / 只读验证路由，真实 GitHub 响应通过，凭据不落盘、不改远端。

正式入口恢复为隐藏后台服务，沿用原私有配置路径；启动前核对 5220 未被占用，配置和索引均不存在，启动后仍保持原存在性、无任务与无台账；production 身份及新资源 200 / demo 404 已核验。未向正式入口写入测试项目，截图的已完成配置场景来自隔离 Git 测试仓。原用户复审文档保持原 SHA256。

### 差异文件树直接选择

用户入口保持在基线核验的差异报告内：展开完整差异树，勾选文件或目录，确认同一处的内部保留范围，保存并重新核验原 U0 / I0。默认不选择所有差异；高级手工路径编辑折叠。选择目录是明确的整个目录规则，不局限于当前页、筛选结果或当前已存在文件；子文件显示继承且不能单独取消目录覆盖。逐文件选择显示目录半选，取消目录后恢复为可逐项选择。

空 / 部分 / 全部选择都显示保留清单和剩余差异计数，最终以完整核验为准。草稿搜索 / 翻页 / 刷新保留，报告外已有规则不丢失。保存失败或核验失败提供本区反馈：前者不写配置，后者保留已保存规则但不登记基线、不修改 main，可继续选择重试。仓库 / 分支 / 模式草稿变化阻止套用旧报告；已启用、正在审核、历史和本地文件管理的规则只读。后端专用保存只接受路径与当前绑定 / 配置版本，不覆盖仓库、API、检查、认证；原 Token 在相同仓库与 API 的规则调整中保留内存，不落盘，不跨项目或接口身份复用。界面沿用当前文件树 / 卡片与状态颜色，覆盖桌面和移动端。

本轮证据：先观察专用保存入口 UNKNOWN_ACTION 和差异树未展开的 RED，再实现并核验。最终 Node 179/179，十三组浏览器旅程通过；最后的文件树旅程另行复验输入修正后清除旧提示。覆盖 65 个目录文件跨页继承、目录半选 / 取消、报告外规则、刷新草稿、配置变化拦截、保存后核验失败继续补选、已启用只读、真实 Git 候选精确保留 README 并更新核心文件。特殊文件名禁用不能精确表达的逐项选择，避免换行或首尾空白被拆成其他规则；既有特殊规则不能从本入口改写。内容查看刷新后保持展开。172 个代码与相关 CSS 的 Biome 检查零警告，语法 / Manifest / MCP 3/3，行数和 diff 检查通过。正式 5220 在配置锁内核验空闲后重启，production 身份、新资源 200、demo 404、原配置与索引存在性保持；未用真实入口保存测试仓配置。界面截图来自独立 Git 测试仓，不能作为用户内网验收证据。

最终 Node 173/173；十二组浏览器旅程通过；语法 / Manifest / MCP 3/3；165 个代码文件与新增配置 CSS 的 Biome lint 零警告，代码行数 / diff 检查通过。新旅程执行两笔真实隔离 Git 同步：API 网页不同域、项目路径自动生成、Token 内存认证与刷新不回显、已有基线后确认、两个旧式 MR、共享 Issue 第一笔保持打开 / 全部接收后关闭。API 创建回执丢失后新 Receiver 回读原对象、重复 / 变化 MR、凭据隔离、旧配置拒绝与停服清除均覆盖。最终严格规则下，版本模式整文件保留（含精确二进制对象）、核心差异拦截、旧非空合并规则不改写及旧空规则绑定兼容均通过。

首次浏览器批量运行曾在页面加载阶段超时，同一测试单独重跑通过；移除文件合并能力后，测试文案与旧的合并结果 / 三次执行预期也一并更新为整文件保留、失败与恢复两次记录。最终十二组均逐组通过；不会用旧范围的测试结果替代最终规则验证。正式 5220 在配置锁内核验空闲后用原私有路径启动，production 身份、新静态资源及旧编辑 / demo 路由 404 已核验，原配置与项目索引存在性保持。

系统 CA 合并保留默认 / 额外信任，证书核验不关闭；旧 Node 支持情况明确提示。实际 CodeHub 的基础创建来自用户内网测试，完整新功能来自作者的隔离 Git / API 合同回归。当前环境访问该站点被重置，没有在用户内网创建对象或验收新版，不把公开云 CodeArts 协议代替其 CodeHub。
