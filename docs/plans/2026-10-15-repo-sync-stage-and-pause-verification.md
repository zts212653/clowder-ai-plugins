# 同步步骤、合入核验与逐笔暂停修复

本次在 PR #77 的现有 `feat/repo-sync-plugin` 分支继续修复，保留用户已推送的 `5e10a3c`，不拆 PR、不合入 main。

## 用户实际操作

1. 选择目标 tag / commit 后，先看到完整五阶段及固定业务子步骤。过程模式包含 17 行，版本模式包含 13 行；同模式的行不会随命令或 Issue 数量增长。没有 Issue 时对应行标注不适用，不创建虚构 Issue。
2. 开始前选择“后续 PR 处理方式”。已在同步的项目也可以在顶部“本轮接收节奏”保存“每笔完成后暂停”，或点击“本笔完成后暂停”。不可中断的事务执行中暂不可修改，待原任务返回后设置。
3. 通过“打开内部 PR”在平台人工审核合入。合入回读、核心文件与历史核验、Issue 处理、接收结果和执行记录均属于第五步。
4. 选择逐笔暂停后，系统完成本笔第五步才进入 PAUSED。下一笔尚未创建 Issue、候选或 PR；页面明确显示停在两笔之间，并保留上一笔完整流程和时间。
5. 只有“继续下一笔同步”放行下一笔；策略仍是每笔完成后暂停。改为连续同步只改变偏好，不能自行放行已经暂停的边界。刷新、服务重启和后台观察也不能放行。
6. 当前及异常阶段默认展开；已完成阶段默认折叠。手动展开、收起或展开全部按交付分别保存在当前浏览器会话，不被轮询覆盖，也不串到下一笔。正常连续处理时明确显示新的来源 PR / 提交。

## 根因与修复

| 问题 | 已确认根因 | 修复 |
|---|---|---|
| 子步骤不断增加 | 原始命令、每个 Issue、重试事件直接成为新的业务行 | 固定业务计划，低层事件按父子关系投影为该行证据；保留所有尝试、时间和安全错误 |
| 合入后回到第二步 | `resume-sync` 默认归到准备阶段；恢复下载和关单没有明确父阶段；主阶段又依据旧交付状态 | 明确登记、准备和核验执行范围；核验子事件保持第五步；初次渲染与轮询使用同一主阶段判定 |
| 候选检查失败被标到发布阶段 | 已有候选 SHA 被状态推导当作准备完成，直播更新覆盖真实失败阶段 | 初次渲染和实时更新统一优先本交付的实际失败步骤；执行记录保存失败仍单独优先第五步 |
| 折叠串笔或手动展开被关掉 | 缓存只区分 current；切阶段时直接关闭所有其他阶段 | 缓存加入交付身份；仅自动收起未被手动指定的已完成阶段；展开全部也保存选择 |
| 暂停后不观察当前 PR | 旧暂停立即进入 PAUSED；观察服务不再恢复；恢复又一次启动下一笔 | 持久保存暂停边界，在本笔接收完成后才停；后台仅观察，下一笔登记时在原写锁内再次核对 |
| 前一笔历史出现下一笔步骤 | 同一恢复任务跨两笔；下一笔入场时尚无交付 ID | 登记新交付时仅回填当前入场子树归属；真正轮次扫描和已有交付保持原归属 |
| 未知失败藏在折叠证据中 | 外层成功被当作全部子事件都已恢复 | 未处理的子失败始终显示 × 与安全错误；同一对象明确重试成功才解除 |
| 旧页面控件误用新状态 | 刷新先换快照、后加载历史；焦点恢复又可能带回旧策略 | 旧页面提交在捕获阶段校验渲染范围；执行前再次核对；策略草稿按轮次和服务基线隔离 |

## 状态与恢复约束

- 新增可选 `continuation` 和 `pauseRequested`，旧台账仍可读取，损坏字段拒绝执行，不重新初始化。
- 当前 PR 等待合入时，暂停请求仍保留 WAITING_REVIEW；第五步报错保留 FAILED 和原暂停请求。恢复查询原 Issue / PR / 候选，完成本笔后仍停在边界。
- 后台 `resume-sync` 明确为观察操作，不能释放 PAUSED / FAILED。显式继续也不能绕过当前交付的核验与关单。
- 完成最后一笔且队列为空时为 COMPLETE，不增加没有下一笔的暂停。
- 只保存安全配置摘要、SHA 映射和脱敏错误；Token 不进入台账、执行记录、浏览器草稿或公开报告。服务重启后，内存 Token 仍需按原安全策略重新提供。

## 验证范围

Windows、Node 24、真实隔离 Git 仓库、真实 Tasks / HTTP 服务和 Chromium。平台 PR / Issue 回执使用受控替身，不访问内网或使用真实 Token。正式试用入口不灌入测试配置、台账或演示数据。

- 新增边界合同：等待合入安排暂停、关单异常恢复、重启、过期观察任务、入场写锁竞争、策略切换、旧格式兼容。
- 新增真实 Git 阶段回归：准备为第二步、核验为第五步、下一笔登记 / 准备为第一 / 二步；固定业务行数量；手动展开刷新保留而下一笔不继承；真实 Git 失败在折叠外显示。
- 新增三笔浏览器旅程：两笔 PR 来源和一笔无 PR 主干提交；共三个内部 PR、两个 Issue；每笔完成后暂停，刷新及服务重启后仍不启动下一笔，明确继续后完成。
- 新增任务归属落盘 / 重读、历史过滤、焦点策略隔离及旧页面动作范围回归。
- 原手工兼容路径、Issue 复用与接收条件关单、台账失败、执行记录补存、PR 引用恢复、秘密隔离、历史只读及移动端断言继续保留。

包含 Chromium 的七项阶段回归单独列入 `test:browser`，纯 Node / Git / HTTP 清单不再隐含浏览器安装依赖。混跑时曾发生浏览器夹具整体超时，未计为通过；同一业务路径单独执行可完成。另确认 Windows 测试浏览器退出后，继承的输出管道可能让关闭事件悬挂；清理改动仅属于测试夹具，不能当作同步引擎修复或降低业务断言。
