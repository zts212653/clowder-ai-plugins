# PR #77 实际使用可靠性修复

来源：用户实际使用反馈及 PR #77 评论 6142020921。所有改动在原分支、同一 PR。

交付目标：正式服务不包含演示启动或平台模拟；大量文件可搜索、按目录浏览；每项阻塞有对应处理入口；错误 PR 引用可安全纠正，平台自动创建能力必须真实且可恢复。

## 状态与边界

- Git 负责候选提交和分支推送，正式向导默认通过平台 push-options 扩展自动创建 PR；默认 GitLab 兼容选项可在私有配置替换。固定 executable/args 命令适配器是额外路径，网页不能指定命令。不支持创建扩展时暂停，不默认改为手工创建。
- Git 路径先保存创建意图，推送携带创建选项，核验回执链接和候选 ref；结果不明不重复推送。命令适配器先按 deliveryId 查询，再保存意图、创建、查询并核验身份与冻结 base/head。两种路径均不自动合入，Git 回执不冒充平台属性 API 回读。
- 人工链接只是操作者确认的引用，不声称平台 API 已验证。只允许 HTTPS，按配置的内部网页仓库范围核验。错误链接可以替换或撤销；必须匹配旧链接、活动交付和远端未合入基线。保留旧引用审计；不删除平台对象、候选或历史。
- 已合入或 main 改变后禁止退回/替换，保留原交付进行 Git 归属核验。取消版本交付仍只允许未发布状态。
- U0/I0 差异报告完整分类，历史错误与文件差异分开。首次登记前可明确选择文件归属并重核验；已启用规则不可静默修改。共同修改、内部保留及未声明核心差异保持不同处理合同。
- 所有产品资产、CLI、HTTP 路由移除 demo。合成 Git 夹具只在 test 下运行，无长期服务或正式入口。升级不删除配置、台账、候选和用户数据。

## 验证矩阵

PR 错误主机/仓库首页/并发旧表单/纠正/撤销/合入后保护；自动创建已有对象/多对象/不匹配/超时与回执丢失/重启只查询；125+ 差异完整性、250+ 文件搜索分页与移动端；基线选择错误和历史不合法；冲突、标签移动、源/内部改写、候选推送不明、进程取消和锁保护回归；生产制品无 demo 路由/脚本，fresh consumer 可启动正式工作台。

真实内网的平台协议尚未提供，自动创建适配器以独立测试脚本验证协议和故障，不冒充该平台验收。

## 新反馈：网页来源与 Windows 文件占用

来源：PR #77 评论 6145625638。SSH 克隆地址只用于 Git 传输，不能用主机和端口推断 HTTPS 网页来源。未声明 internalWebUrl 时，生产对象登记提示 INTERNAL_WEB_URL_REQUIRED；配置后以精确 origin 和仓库路径边界核验 PR / Issue。仓库设置始终提供独立入口，PR 当前步骤缺地址时展示补填表单和直接主操作。缺失地址的旧人工引用可补填匹配的范围，创建驱动保持不变；已有自动创建意图的配置仍冻结。

台账、配置、模式设置和执行记录共用按规范化文件路径协调的原子读写。同进程不同 Store 实例的状态读取与替换互斥，仅保护短暂文件操作，不阻塞整个 Git 同步。外部读取或安全软件产生的 EPERM/EACCES/EBUSY 只重试同一个 rename，最多 7 次、累计等待约 1 秒；不重跑业务动作、Git 或 PR 创建。不先删除/截断目标文件，失败只清理本次独占创建的临时文件。

持久失败通过 LEDGER_WRITE_FAILED / PRIVATE_WRITE_FAILED 固定脱敏诊断显示。最终台账提交有独立“保存交付台账”阶段，失败显示 ×，已保存的执行记录支持刷新与重启回读。台账自身无法写入时不能保证 delivery.error 写入该文件；回读旧台账和 Git 才是恢复依据，不能将内存变化描述为已提交。若整个私有目录不能写入，先修复权限/占用再恢复，不能声称记录已持久化。原跨进程单写锁和停止不明保留规则不变。
