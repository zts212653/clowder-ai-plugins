# Automatic issue origin and operating system

Accepted source: thread `thread_mucwsgsjtlbabfcq`, user message
`0001792640418907-000043-e92112f3`. Continue original PR #80 and existing Task;
the separate production Host installation gap remains open.

The workbench classifies issue content into internal, external, shared or unknown
origin, plus Windows, macOS or other affected systems (multiple allowed). CodeAgent
and CodeHub are explicit internal clues. Repository visibility does not determine
origin. Conflicting or insufficient clues remain unknown. Normal comparison systems,
unchecked template choices and HTML comments do not become affected environments.
An explicit environment/operating-system section takes precedence over background
platform names; an unfilled section retains title evidence. Fenced code examples
are excluded from operating-system evidence. Real issue #279 reports macOS even
though its description discusses existing Linux and Windows installation scripts.

The plugin owns one conservative rules module used by the browser and the projection
of persisted cat analyses. Lists start from available titles or matching stored
analysis bodies. The detail reader passes already authorized body observations to the
current workbench; full source identity, title and update stamp fence their reuse.
Changing source content or losing access prevents stale body-backed suggestions.
No provider labels, existing manual records, source archives, SDK schema, or Host
code change. Cat instructions ask for semantic origin/system reasoning as well.

Two read-only result rows, expandable evidence and overview filters extend the
accepted classification-first interface. Existing Feature grouping and optional
manual tags remain available. Newly edited local tags are prefilled once from the
automatic results; authored work is not overwritten. The save bar stays visible
when the additional result rows make the mobile editor taller.

Validation covers description-based results, normal comparison systems, multiple
OSes, missing/conflicting evidence, stale analyses, manual-data preservation, packed
browser filters, source revocation, mobile layout, and isolated Host/sandbox journeys.
The source export still reproduces from Core commit `0312447` through the existing
explicit plugin adapter, with all original source hashes unchanged. No Core edits.

This is a rules-based candidate classification, not a measured semantic accuracy
claim. The category seed and original model provenance are retained as-is. User
corrections remain local, and no real model call or dispatch is needed to show the
new dimensions in the trial environment.
