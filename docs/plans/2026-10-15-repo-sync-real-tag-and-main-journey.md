# 真实发布 tag 与混合主干提交的接收旅程

用户用公开来源仓验证两条路径：v0.1.0 → v0.1.1 报 TARGET_NOT_FORWARD；改为 v0.1.2 后报 SOURCE_UNPROVEN。此前隔离 Git / API 合同的完整测试及真实 GitHub 只读接口验证，未覆盖这个仓库的整个真实版本区间，不能作为该场景已可用的证明。

## 已查证根因

- v0.1.1 的 commit 包含 v0.1.0，但不是当前 main 的祖先。旧校验把“没有前进”和“不在来源分支”合并为一个报错，并把过程模式的分支限制用于版本模式，导致独立发布 tag 无法接收。
- v0.1.0 到 v0.1.2 的 first-parent 区间包含未关联 PR 的版本发布与文档提交。旧实现假定每个主干提交必须对应唯一 PR，因而中断整轮读取。
- 目标 tag 控件沿用较小字号和高度，缺少显式宽控件布局。按实际 DOM 尺寸补可读性检查，而非只断言元素存在。

## 处理合同

1. 过程模式仍要求来源分支连续历史和完整 PR 合入边界。目标不在来源分支、目标回退 / 分叉、PR 内部提交分别反馈；错误包含相关提交短 SHA 和处理方式，校验在原流程子步骤内显示 ×。
2. 版本模式允许来源仓已发布 tag 位于独立发布分支；它须包含上次接收提交。登记基线支持来源分支 commit 或当前有效 tag 的 commit，从同一来源冻结并下载对象；不接受把其他本地对象当来源。
3. 版本模式的选择、发起、候选检查与发布都回读冻结 tag；不再错误要求该 tag 已在 main。内部基线、核心一致、整文件保留、候选 head / base、合入结果与恢复核验继续生效。不增加三方合并。
4. 过程模式默认列出无关联 PR 的主干提交并暂停。用户明确勾选本轮包含后，才将每个此类提交作为独立来源交付，顺序与 PR 混排，每笔对应正常内部 PR。来源、标题、历史、接受游标与请求幂等身份区分 PR 和 commit；不伪造 PR、不跳过代码、不重置原台账。
5. API 错误、关联数据缺失、多义 PR、边界不匹配仍暂停。只有完整读取后明确空关联可归为无 PR 提交。确认使用布尔参数并冻结在本轮记录，不能隐式降级或将字符串当授权。
6. 无 PR 提交仍按原消息查找 Issue 候选，但关闭关系只采用匹配本笔实际 commit 的关闭事件。无 PR 身份时不能把空 closer 或人工关闭误判为同源关闭；内部 Issue 创建、关联、接收条件和合入后关单沿用同一机制。
7. tag 控件独占一行、使用可用宽度、至少 48px 高和 16px 字号；名称和短 SHA 同显，完整对应可展开查看。覆盖 1440px / 390px，按钮与提示分行，不横向溢出。

## 验证与证据边界

先观察旧实现的可信 RED：分支外发布 tag 选择失败、该 tag 作为已有基线时对象不可读、过程模式泛化错误、控件尺寸过小，以及无 PR 主干提交整批被拒绝。另增加无 PR 身份不能匹配人工关闭事件的检查。

隔离回归覆盖分支外 tag 从登记、选择、发起到候选、正常合入与恢复完成；回退、分叉、标签移动及新编号不能绕过保护。混合过程覆盖默认暂停、明确选择、原对象保留、逐笔内部 PR、共享 Issue 与恢复，外加完整浏览器交互。

真实来源验证只从公开 GitHub 读取 Git、PR / Issue 及关系；内部接收、推送和模拟审核全部在新建本地隔离 Git 仓完成。真实来源区间的完整接收结果、隔离自动平台合同测试、用户内网平台验收是不同证据，不相互替代。不得向真实来源创建对象或将 Token 写入记录。

所有变更在插件 PR #77 原分支交付，不拆分、不自动合入。公开回复仅使用公开来源证据、脱敏行为与验证结果；正式服务沿用原私有配置，不能写入验证项目。

## 作者验证结果

- 最终 Node 200/200；十五组浏览器旅程全部通过；语法 / Manifest / MCP 3/3；184 个代码 / CSS 文件 Biome 零警告、行数和 diff 检查通过。浏览器的版本路径使用分支外发布 tag，过程路径使用 PR 与无 PR 提交混排，并包含显式确认、共享 Issue 自动创建 / 关联 / 关单失败恢复。
- 真实 GitHub 原生读取 v0.1.0 → v0.1.2 完整清单为 18 笔：15 个 PR，3 个无 PR 主干提交。默认暂停，明确包含后清单覆盖到准确目标 commit。v0.1.1 在过程模式被精确识别为分支外 tag。
- 在线 Git 回读曾出现超时及断连。保留台账后，以同一次真实下载的 Git 快照与已记录的真实 API 清单继续，在本地隔离接收仓回放至 18/18 COMPLETE，未重复创建已经完成的交付；已合入待补元数据的交付先续接记录，禁止重新发起。另一个独立本地接收仓完成 v0.1.0 → v0.1.1 的版本更新。
- 此后段是冻结真实数据回放，验证辅助进程临时映射 Git 来源到该快照，不写入产品或正式服务。内部 PR 引用及审核为本地模拟；实际 GitHub 来源仓未写入，用户内网平台完整验收未宣称通过。
- 正式 5220 在原配置锁内确认原实例空闲后重启，新实例为 production，新控件及无 PR 确认资源可读取，演示路由仍 404；原配置与项目索引保持不存在，无测试项目写入。Windows 启动包装的管道等待单独结束，不影响已启动服务。
- 原用户复审文档保持原 SHA256，未修改。维护者独立审查与 CI 不由作者自检代替，PR 保持 Draft。
