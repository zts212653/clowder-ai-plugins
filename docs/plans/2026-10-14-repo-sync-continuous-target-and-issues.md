# 开发过程同步：目标范围、文件保留与 Issue 自动化

用户已授权在 PR #77 现有分支完整实现：目标 tag / commit 决定本轮终点，按上游已合入 PR 逐笔接收；明确保留内部文件，其他核心文件严格一致；自动创建、关联、关闭 Issue，并保留异常恢复和历史。继续既有五阶段界面、接受游标和台账，不增加竞争的业务状态。

## 约束与状态契约

- continuous 的目标必须位于配置交付分支的 first-parent 历史中，并是完整 PR 的实际接受边界。不能以任意 commit 截断 PR，也不能跳过中间 PR。最新扫描 HEAD 与所选同步终点分开记录；完成所选目标不等于上游实时最新。
- 标签对象和 peeled commit 一并冻结，后续每笔执行重新验证标签及历史。已存在活动交付时不能重选目标。来源没有唯一 PR 证据时暂停，不猜测来源。
- continuous 复用 internalPaths 作为显式保留路径，mergePaths 仍仅用于 version。规则随绑定固定；已有空规则绑定身份保持兼容，新增规则创建不同绑定，不能静默重置台账。
- 保留包括内部已有内容和不存在状态：声明 README.cn.md 后，内部原本没有该文件，就不因上游同名文件而新增。非保留范围的内容、存在性、模式严格一致；跨保留文件 / 核心目录的结构冲突应阻止发布并指出路径。
- 候选仍保留原始来源对象与祖先，内部接收节点使用按规则构造的 tree。PR 只有文档差异时仍作为“仅历史接收”交付，经正常平台审核；平台不支持空内容差异 PR 时显示真实创建错误，不伪造 PR 或自动推进游标。
- 允许在没有活动交付时核验并接管保留路径中的内部后续提交；活动交付冻结后 main 改变必须核对原交付，不覆盖。
- Issue 的身份按 bindingId + sourceId 稳定生成，同一 Issue 跨多个 PR 复用。创建前保存意图，查询、创建后回读；意图存在且查询没有对象时只报告结果不明，不再次创建。映射、关联和状态必须校验仓库与来源身份。
- PR 创建仍使用现有 Git 扩展 / 固定适配器；Issue 自动化提供实际 GitLab 兼容 API 实现和固定 JSON 命令适配器。不能从“支持 Git”推断平台具有通用 Issue 命令。未配置能力时明确阻塞 / 显示人工模式，不能冒充自动完成。
- Issue 关联在具体 PR 存在后完成，校验关联的来源 / 目标分支和候选 SHA。自动关闭仅在实际 Git 合入核验通过、关闭关系成立、全部 requiredTargets 接受后发生；普通关联不自动关闭，共享 Issue 条件不足保持打开。原提交消息的跨编号误关风险继续由平台实测声明阻止推送。
- Issue 变更回执丢失时回读原对象；只对同一个已核验对象进行幂等状态操作。元数据失败保留 CODE_ACCEPTED_PENDING_METADATA，恢复不会重复代码发布或 PR 创建。业务台账失败、最终记录补存、停止不明、跨实例与旧请求保护沿用现有契约。
- 凭据仅从本机环境读取，网页只配置环境变量名和非敏感连接字段；固定命令只能写在私有 JSON。原始平台响应 / 命令输出不进入错误、日志或公开 PR。配置快照只记录受限摘要和标识。

## 实施与验证单元

1. 真实 Git 回归：README 三种路径的保留、核心严格核验、允许的内部后续提交、结构冲突、两笔 PR、空核心差异交付与 tag 改写；先 RED 再实现。
2. 目标发现：tag / 完整 SHA 解析、完整接受边界、有限队列、目标与最新区分、不能重选活动范围。来源查询复用 gh 的真实合同，隔离测试通过受控元数据夹具验证。
3. Issue 生命周期：创建意图、共享对象、PR 关联、条件关单 / 重开、回执丢失、查询失败、身份不匹配、保存失败与重启。使用隔离命令 / HTTP 合同夹具，不产生真实外部 Issue。
4. 正式界面：模式设置内显示保留规则；工作台选择终点、预览逐 PR 队列与忽略文件；阶段 2 自动 Issue，阶段 3 关联，阶段 5 自动关单 / 恢复。历史显示实际自动化证据与配置，保留已有人工模式的显式入口。
5. 回归和制品：包目录执行 node --test test/*.test.mjs、npm run test:browser、npm run lint；Biome 使用已安装的 2.4.1 CLI，按当前根 biome.json 检查本包 MJS；代码 350 行硬限与 git diff --check。npm fresh consumer 保证没有测试服务进入安装制品。
6. 同一分支 commit / push，远端 HEAD 与中文评论逐字回读。空闲时在配置锁内替换唯一正式试用服务，保留私有配置、台账和任务；不执行用户真实仓同步。

真实内网平台未提供产品或扩展协议，不能声称已完成该平台实测；交付实际可配置的生产适配器、接入说明与隔离合同验证。此边界不削减上述插件能力，不引入 demo 产品服务，也不替代维护者对最终 HEAD 的独立审查。

## 已交付与验证

- 目标解析在 source-target / github 中，保留实际扫描 HEAD 并按完整 PR 边界生成队列；每笔继续验证冻结 tag。
- preserved-tree / continuous-preview 将显式内部保留规则贯穿基线、候选和接受核验；原始对象不改写。没有活动交付时仅允许经核验的保留路径提交。
- issue-lifecycle 保存稳定创建、关联和状态意图，issue-adapter 支持固定命令和实际 GitLab 兼容 API。配置查询失败在首次写意图前可修正，写意图后范围固定；关单失败只恢复元数据。
- 正式五阶段界面展示自动化子步骤、保留范围、原对象恢复、平台回读来源；历史可按本轮 tag 搜索，仍保留每笔 PR 身份与当时配置。
