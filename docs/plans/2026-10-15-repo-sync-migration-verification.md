## 已交付的用户旅程

仓库设置新增“导入 / 导出配置与同步进度”。普通设置中折叠显示；导入或源端冻结时，优先显示“认证 → 核验 → 明确启用”。核验按钮位于步骤内，完成后定位首个失败项或报告，仓库和历史摘要按需展开。

- 配置模板只复用设置；完整包保存台账、历史步骤 / 时间、提交映射、Issue / PR 意图与引用、任务和 Git 对象。模板不会暗中初始化基线。
- 包不包含 Token、环境变量值、SSH 密钥、Git 配置 / hooks、临时检查工作目录及机器绝对台账路径。未知配置字段、自定义检查 / 命令适配器 / 推送参数明确拒绝迁移，不执行外来命令。
- 导出完整包冻结源端并暂停轮次。导入为独立项目，接收端保留 `IMPORTED` 门禁；认证、只读核验及唯一执行环境确认后才解除门禁，随后仍需明确继续原同步。
- 同包重试复用原项目，目录已落盘而索引未保存时补登记；不同包不能接管已登记接收分支。常见 SSH / HTTPS 地址写法用于接收权去重，原台账 binding ID 保持不变。
- Token 错误就近直达当前项目认证，展开并聚焦；保存后继续原轮次。输入内部 Token 前显示实际 API 接收地址与项目。跨项目、仓库、轮次或交付变更时阻止错误恢复，历史记录不提供写入恢复按钮。
- 登记锁中断恢复需要确认旧服务及子进程已退出；只有旧 PID 确认为不存在才释放，活进程、权限不足、损坏锁和归属变化均拒绝。

## 已明确的边界

这些结果是 Windows 上独立 Git 仓库、本机平台夹具、真实生产 HTTP / 浏览器与干净安装证据，**不是用户内网 CodeHub 部署验收**。GitHub / CodeHub 测试夹具不代表真实访问权限已经验证，实际网络、证书和写权限由接收环境在真实流程核验。

网页完整包限制同插件版本、128 MiB JSON、32 MiB 逻辑记录、80 MiB Git bundle、10,000 个逻辑文件。超限或自定义命令配置会明确拒绝，不截断历史。完整包仍含私有地址、代码和业务内容，应私下交接。跨机器唯一执行环境需要操作者确认；跨域别名与本机 Git URL rewrite 不提供自动识别保证。

同包重试不覆盖已登记项目修复本机损坏；损坏数据保留后，应停止旧执行器并在新的私有工作台恢复原完整包，核对导出时间和接收位置，防止覆盖后来产生的历史。失败暂存目录保持隔离，不自动删除用户数据。

操作步骤及恢复说明见 [插件 README](../../packages/repo-sync/README.md)。
