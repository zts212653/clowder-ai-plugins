# 同一工作台管理多个同步项目

来源：用户已配置一个同步模式的项目后无法添加另一个模式，要求可选择多个项目。修复继续 PR #77 原分支。根因是一个服务只有一个 createConnection 和 Tasks 对象，启用后禁止覆盖该配置；保护规则正确，但缺少项目管理层。

目标：同一正式入口可新增、命名、选择多个项目；每个项目独立保存仓库、模式、文件规则、基线、Issue/PR 映射、历史与任务。切换不取消后台同步，不把旧页面操作发往另一项目。旧配置和台账原位保留，不能用切换模式覆盖已有绑定。

Architecture cell: 独立 repo-sync 执行器。Map delta: 执行器内新增项目登记与请求范围，未改变应用 Host / MCP 写权限。

## 状态与边界

- 启动参数仍是原私有 config.json。默认项目继续直接使用该文件；读取不会改写原内容、迁移 stateDir 或复制台账。新增项目登记保存在该文件旁的独立项目索引，每个新增项目拥有受控 ID 推导的私有配置目录，网页不能提交路径。
- 选择属于当前页面 URL 的 project 参数，不使用全局“当前项目”指针；两个窗口各自独立。API / 轮询 / 历史 / 表单草稿必须携带同一项目范围。切换清理旧页面投影，保存对应项目草稿，旧任务继续在原执行器与原台账执行。
- 每个项目拥有独立 Tasks 实例与配置锁 / 台账锁。项目 A 的运行或记录补存失败不阻止浏览和配置 B；关闭服务必须处理所有原执行器。不能通过切换绕过 A 的恢复闸门。
- 新增与命名使用索引单写锁和版本比较。未知项目、损坏索引、已登记配置丢失、旧创建请求和项目/请求范围不一致均明确拒绝并保留原件，不能默认为默认项目。
- 同一个已知内部仓库地址 + 合入分支不得在两个项目重复接管，避免两个独立游标竞争同一目标；不同内部仓库或分支允许。无法从地址完全证明 SSH/HTTPS 别名，不能声称自动检测所有别名。
- 原始单项目 API 测试 / CLI 私有文件路径保持兼容；正式 CLI setup/serve 与 MCP 打开的工作台接入多项目管理。MCP 仍只提供受限状态和打开入口，不增加自动推送、合入或建单工具。
- 不提供项目删除或重置操作；不得为了验证修改用户真实仓库或清空持久记录。

## 实施与验收

1. 先用隔离配置证明旧实现没有多项目入口，并补项目登记 / 默认配置原位保留 / 模式并存 / 跨实例创建竞争 / 损坏索引 / 目标重复保护的 RED 用例。
2. 增加项目索引和范围化连接，扩展 HTTP 请求及 Tasks 路由；测试 A 后台执行时 B 可配置和执行、旧请求不能跨项目、历史不会混入。
3. 顶部项目选择与“新增项目”入口；新增后进入该项目配置，已启用项目可随时回看。草稿 / 展开 / 历史筛选 / 轮询均按项目隔离，覆盖加载、空白、已配置、异常、后台执行和移动端。
4. 跑包内 Node 全量回归、受影响浏览器旅程、fresh consumer、npm run lint、Biome 及 350 行 / diff 检查。截图只在本机留证，公开回复只含合成结论。
5. 正常 commit / push 到 PR #77 原分支。更新真实试用服务前核对所有项目任务，在配置锁内确认空闲与进程归属；保留配置、索引和全部台账。中文 PR 回复使用 UTF-8 文件并远端逐字回读。

## 作者验证结果

实现了项目索引、独立连接 / Tasks / 私有配置与顶部项目导航。默认配置原位读取；新增配置放在索引旁目录，新增台账在私有根目录使用较短的身份摘要目录。后者修复了 Windows 下嵌套目录过长导致候选 Git 检查报 `$GIT_DIR too big` 的实际回归，完整绑定身份仍由台账核验。

RED → GREEN：原正式 CLI 没有新增项目 API；切换回同一配置页面会在状态载入前覆盖草稿；页面尚未载入时点击导航产生前端异常。现已通过带真实 Git 的两项目浏览器旅程：A 后台任务未结束，B 配置另一模式、准备候选、核验合入并查看历史，之后切回 A 原配置 / 台账字节不变。多窗口互不改选、1440 / 390 无横向溢出、新增回执丢失复用原项目均有断言。

完整 Node 回归 152/152，十一组浏览器旅程通过，含 fresh npm consumer 与正式 CLI 启动；Manifest / MCP 3/3、语法、146 个文件的 Biome lint 零警告、350 行硬限及 diff 检查通过。缺失 / 损坏项目索引、已登记配置丢失、旧请求跨项目、目标重复接管与并发登记均保留原件并拒绝；某项目配置损坏时，正常索引仍允许通过正式 HTTP 入口选择其他健康项目。

正式试用入口已用原私有配置安全更新，真实浏览器确认顶部新增项目表单及原草稿保留。没有给用户入口写测试项目、改变其仓库或清空任何持久数据。截图只在本机保存；平台和网络夹具是测试合同，不代替真实内网验收。以上是作者验证；保持原 PR，由维护者独立审查，不自批或合入。
