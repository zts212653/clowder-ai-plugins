## 需要纠正的关键推论

### 1. 台账可读、结构合法、事实可信是三个层次

当前源码 `Store.read`、`Receiver.read`、`assertLedger` 对读取、格式、绑定、映射与状态做检查；配置摘要还有内容指纹。它们不构成对台账的数字签名，不能据此声称“文件从未被手动修改”。后续 Git 历史、核心内容和平台对象回读仍是执行前的事实核验。

已有正常台账的项目本来就走续接，不重新申请 U0/I0 初始化。最后一条按时间排序的 COMPLETE 记录不能无条件替代当前 `accepted` 游标。例如：第二笔 PR 的代码已合入，Issue 关单失败，状态为 `CODE_ACCEPTED_PENDING_METADATA`；此时退回第一笔 COMPLETE 重新同步，会丢失已接受代码的事实和原关单恢复路径。

当前游标也可能来自初始接管，或核验了仅保留路径的内部后续提交；这两种情况未必存在一笔包含当前完整 SHA 对的交付。展示来源时允许这些情况，不能改写历史交付以凑出匹配，信息不足标“未记录”。

损坏/无权读取的台账与真正不存在的台账必须区别处理。前者保留原文件并恢复、核验；后者首次接管可以由用户提供起点。无可靠备份时，本次只提供诊断与独立接管说明，不实现同绑定的自动重建、迁移或“忽略台账损坏”开关。

若外部 SHA 还留在对象库，但已不满足来源历史或有效 tag 的接收条件，也应暂停。仅能 `cat-file` 读到对象不等于来源关系仍成立。

### 2. README 路径不会互相继承保留规则

规则按精确路径或显式目录前缀匹配：

| 当前规则 | 对后来新增的外部 README.cn.md 的处理 |
|---|---|
| 只保留 README.md | 未匹配，满足其他核验条件时跟随外部进入 |
| 保留 README.md 与 README.en.md | 仍未匹配，满足其他核验条件时跟随外部进入 |
| 同时保留 README.cn.md，内部目前没有该文件 | 匹配，保留内部“不存在”的状态，不引入外部文件 |

所以不采纳原反馈中前两种场景“未在保留列表中，因此永远不会进入”的结论，正确关系恰好相反。也不将“不保留”写成直接覆盖承诺：已有未声明核心差异会先阻断接管/同步，而不是悄悄删掉内部专属文件。

目录规则覆盖目录下未来文件；单个文件规则不覆盖同名变体。“当前规则生效期间不接收该路径更新”比“永远不会”准确。

原反馈建议同步后在内部 PR 添加文件，再加入保留列表；其前半部分可用于维护已保留内容，后半部分不能突破启用后的冻结规则。同一内部仓库/接收分支也不能靠新建项目重复接管。独立项目只适用于另一独立接收范围，例如另一目标分支，并需核验；同一范围改变规则须另行设计迁移。本次没有该迁移入口，不用“复制配置”冒充解决办法。

### 3. 时间阈值应解释等待，不能改变执行结果

Git 未输出进度可能是阶段切换、输出格式不匹配或后台仍在工作。页面需要同时展示“任务状态最近成功读取时间”和“Git 最近进度时间”。约 30 秒无新进度可将百分比标为过时，约 5 分钟提示耗时较长；都不等同于命令超时。真正超时沿用当前配置，取消受执行器实时可取消状态约束。

首次读取完整来源集合之前，本轮总数未知；不能为了始终显示 `3/8` 而把部分清单当作完整清单。人工审核只显示等待时长和 PR 链接，不估计合入时间。

### 4. 可用性目标不能冒充已验证指标

采纳实际参与者、独立任务、完成率与耗时记录的方向。暂不将未经试点的 8/12/3 分钟当作产品 SLA，也不将过程模式 3/5 完成视为比版本模式更低的正式质量门槛。两个模式都应帮助多数用户完成对应目标。

故意输入过期 Token，应产生明确、可恢复的失败；不应为了“零配置错误”吞掉校验。GitHub 来源 Token 本来只需读权限，反馈中的“只有 read、没有 write”适用于内部创建/关单权限测试，不能据此判定来源 Token 无效。网络失败也不能误标为认证失败。

参与者尚未组织时如实记录“可用性试验未执行”。自动化和独立 Agent 检查可以提供工程证据，不能计为 5 名真实开发者的无提示可用性测试。

## 对暂不纳入范围的补充说明

| 能力 | 有价值的使用场景 | 本次未纳入与重新评估条件 |
|---|---|---|
| 持久密钥保管 | 服务频繁重启、无人值守 | 需独立评估宿主密钥库、解锁和跨项目隔离；不默认新增浏览器密钥副本，不承诺版本日期 |
| 多项目批量检查/同步 | 定期查看多个项目、集中发起更新 | 需真实使用量证明收益，明确部分成功、单项目恢复和权限边界；不用“全部回滚”作为能够保证的默认承诺 |
| 完整历史导出 | 本地归档与运维审计 | 需明确字段、脱敏和保存对象，避免将内部配置整体导出；本次提供只读回看和可预览摘要 |
| 外部通知、完整图谱 | 跨人协作、复杂来源追溯 | 需先有明确接收方、数据边界和查询任务；当前方案不新增消息外发或图谱导航 |

“本次不采用”表示该方法与当前目标/边界不合，例如把最新 main 猜作历史基线、以文件扩展名推定归属；“暂不纳入”表示可能有价值但需独立设计。二者都不等于已经安排下一版本开发。
