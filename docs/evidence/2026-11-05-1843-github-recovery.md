# Complete PR and Issue schedules

This implements C of [the accepted execution plan](https://github.com/zts212653/clowder-ai/issues/1843#issuecomment-6628267251), with the [Host storage boundary](https://github.com/zts212653/clowder-ai/issues/1843#issuecomment-6646884259) and [complete-entry scope](https://github.com/zts212653/clowder-ai/issues/1843#issuecomment-6649252373). The measurement boundary is the fully awaited `github.pr-tracking` and `github.issue-tracking` actions. Their existing typed, community collection, journal and migrated-issue consumers all remain connected.

Candidate versions are GitHub Operations `0.1.0-alpha.37` and SDK `0.3.0-beta.2-candidate.11`. This document records author validation, not review approval, publication, runtime adoption or final acceptance.

## Original ownership and derived access

| Owner | Canonical facts retained | Derived bounded access |
| --- | --- | --- |
| Typed wait storage | Original ID, condition/generation, baseline, outcome, outbox and owner recovery metadata | PR/Issue due projections; malformed records retain original bytes and leave the automatic queue |
| Community collection | Original collection row, canonical route identity, cancellation, observation cursors, retry facts and notice intent | Separate PR/Issue due projections |
| Community journal | Original global append reservation, immutable event IDs/global order; metadata adds subject positions, exact references and route reconciliation debt | Direct global/subject event references; PR/Issue pending projections |
| Migrated Issue | Original Host Task binding/version, private legacy cursor and stable outbox key; no fabricated typed registration | Original owner's due projection |
| Host private storage | Original namespaced value/revision and same-version projection metadata | Atomic indexed CAS, bounded due read and version-fenced rebuild; no GitHub business decisions |
| SDK | Optional forwarding of Host capabilities through existing facades/worker | Capability discovery remains explicit; no prefix HSCAN fallback |

There are eight named indexes at most: typed PR/Issue/invalid, journal PR/Issue, collection PR/Issue and migrated Issue. Status notice intents stay on the original owner's record and share that owner's projection. Successful notice receipts and finite notice failures do not authorize a wake or change business completion.

Each owner explicitly prepares a resumable census before declaring readiness. Its cursor/checkpoints survive interruption. Normal ticks read the readiness record and at most 20 due records per owner; they do not repeat namespace scans. The journal finishes the original append reservation and publishes the corresponding references/pending debt before advancing its control row. A stale acknowledgement cannot erase a newer route. Cancellation and terminal history survive rebuild.

All affected writers use the same original-owner indexed publication. The Host updates value/revision, projection metadata and membership in one Lua operation. An old writer cannot replace an already indexed value while silently leaving a stale score. Indexes can be rebuilt; original failures, outcomes, cursors and IDs are not recreated from the indexes.

Normal open waits, quota deferral, timer clipping and records not entered in the current batch do not spend a failure attempt. Five real failures leave the original record in `needs_attention`; they do not invent successful completion. Original-thread status notices are idempotent and do not wake a cat. Unavailable owner/receipt state remains visible for inspection.
