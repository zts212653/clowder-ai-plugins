# 飞书纪要：插件记录、通知与 MCP 读取

飞书纪要插件保存获准发现的会议记录，通过普通 Host 消息通知所选对话，猫再经已安装插件的 MCP 读取记录对应来源。用户保留账号授权、来源读取许可、目标选择及说话人／产出判断。插件不增加总结器、家庭记忆副本、Needs Me 生产者或隐式历史重放。

本文是 C2／独立后续的产品化设计。当前源码与本地候选不代表官方发布、目录准入或完整安装验收，也不构成未关闭的 C1 尾项。

## 职责与身份

插件拥有账号适配、隔离凭据、会议元数据索引、来源引用、游标、待发送通知和补采选择。来源正文及修订以飞书为准；获准保留的本地快照记录准确来源，默认不因时间经过而删除。

Host 拥有安装与制品校验、授权、普通用户／线程／调用身份、module 生命周期、目标路由和消息去重。来源元数据和工具正文不能指定另一用户、任意文件根、来源 URL 或目标线程，也不能制造 Host 权限。

## 生命周期与控制

生产 manifest 声明 builtin 控制模块及 MCP 读取入口。MCP 载体通过已认证的 module action client 调用记录方法，不取得凭据目录或直接访问记录文件，不增加辅助监听器或专用 Host 会议回调路由。

模块运行健康、账号认证、持久化的采集意图和实际采集器是不同状态。启动控制模块不隐式登录或采集；登录成功不自动开启采集。状态与列表读取不启动、补采或修复数据。停止、取消、授权撤销和晚到结果均须检查实际生命周期与调用身份；凭据缓存、进程退出或 stdout 不能单独证明授权成功或未发生副作用。

凭据与子进程由插件隔离和回收。中断后的授权状态须由新的 owner 操作依据实际账号、应用、scope 和尝试记录核对，不能盲目重试 token 交换或借已结束请求继续授权。

## 记录与通知

来源身份和修订确定同一条持久记录。记录和稳定通知意图先保存，再调用普通 `messaging.send`；确认回执后保存投递结果。响应丢失时保留相同目标、去重键与正文，不能另造记录或把不确定发送改投另一线程。游标推进不能丢失已发现的记录及通知意图，失败不清空待发状态。

记录的不可变意图与可变回执分别绑定完整性校验，私有密钥与记录一起保留。缺失或损坏密钥、未绑定的旧记录进入需要恢复状态，不能静默重签、迁移或删除。完整性校验不提供授权、不证明来源真实性，也不能抵御私有目录与密钥同时失陷或有效旧快照回滚。

通知将 provider 标题作为有界、不可信数据处理，清理控制／换行和双向格式字符，并在独立数据行编码；标题不能注入额外指令行。该处理不宣称模型不会误读引用的数据。

补采保留扫描指纹和用户对“仅未来／重放”的明确选择。普通记录、授权历史与确认过的消息不会因停用或撤销被删除。

## MCP 与读取边界

`cat_cafe_meeting_records_list` 返回有界元数据页；`cat_cafe_meeting_records_read` 通过记录 ID、偏移和数量读取。工具名、参数和能力以 [plugin.yaml](../packages/feishu-meeting-intake/plugin.yaml) 为准。读取与异步来源工作前后均验证当前实例、调用者、授权和范围，不能把最新版正文标作记录保存的旧修订。

分页内存有界，列表是实时视图而非快照；保留记录增多仍会增加目录扫描成本。单写者与私有目录是运行前提，同进程序列化不表示支持任意跨进程并发写入。

## 验证与分发限制

[包说明](../packages/feishu-meeting-intake/README.md)提供配置、构建与使用方法。[接口基线](../docs/plugin-development.md)定义普通 Host 能力，不能恢复已删除的 broker、事件发布、专用 intake、sourceGrant 或旧卡片流程。

验证区分记录／通知与 isolated sender 测试、私有文件与子进程测试、实际 packed consumer，以及真实 Host／飞书账号旅程。测试应覆盖重复发现、失去发送回执、重开、并发、撤销、篡改、收据不匹配和修订变化；任一组件通过不能代替另一条旅程。

插件保持官方目录与发布之外。Meeting pack-gate 豁免不代表普通打包门禁通过；实际构建、打包、依赖闭包和消费者仍须独立验证。现有反馈和历史数据不因本文被删除、重放或重新授权。
